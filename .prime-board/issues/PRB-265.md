# Search: manejar entradas FTS malformadas sin exponer SQLite

Created by admin.

## Hallazgo reproducible

El filtro de búsqueda no convierte todas las entradas de usuario en una consulta FTS válida. `search: "\"\""` hace que `ftsQuery` genere una expresión vacía y GraphQL devuelve el error interno de SQLite `fts5: syntax error near ""` en lugar de una respuesta controlada. Otros valores como `"unclosed` o `*` devuelven cero resultados sin una semántica documentada.

## Evidencia

- `apps/server/src/domain/filters.ts`: `ftsQuery` conserva frases vacías y las pasa a `MATCH`.
- Reproducción aislada con `createTestApp`: `issues(filter: { search: "\"\"" })` responde `data: null` y error FTS5.
- El error expone un detalle interno de SQLite al cliente.

## Comportamiento esperado

La búsqueda debe tratar entradas vacías/malformadas de forma determinista: ignorarlas, devolver cero resultados o producir `VALIDATION_FAILED` con un mensaje público, pero nunca filtrar un error interno de SQLite.

## Criterios de aceptación

- [ ] Frases vacías y comillas sin cerrar no provocan errores internos.
- [ ] Se define y documenta la semántica de `*`, comillas y búsqueda vacía.
- [ ] El comportamiento es estable dentro de filtros `and`/`or` y paginación.
- [ ] Hay regresiones para entradas FTS adversariales.
