# GraphQL: devolver NOT_FOUND para Initiatives vacías de otro Workspace

Created by Builder.

## Hallazgo reproducible

La revisión de PRB-587 encontró una diferencia de aislamiento en SQLite. Con dos Workspaces, una `initiativeUpdate` dirigida al ID de una Initiative del Workspace ajeno, sin Teams ni Projects relacionados, y con `teamIds: []` y `projectIds: []`, llega al dispatcher de alcance y devuelve `UNAUTHORIZED` en vez de `NOT_FOUND`.

`initiativeRelationTeams()` comprueba la existencia con `SELECT id FROM initiatives WHERE id = ?1`, sin filtrar por el Workspace efectivo. Al no encontrar relaciones, el dispatcher produce `__workspace__` y una key limitada falla por autorización antes de que el resolver scoped pueda ocultar el recurso.

## Comportamiento esperado

Un ID de Initiative de otro Workspace debe devolver `NOT_FOUND` de forma consistente, incluso cuando la Initiative no tenga relaciones. La respuesta no debe depender de que existan Teams o Projects relacionados.

## Criterios de aceptación

- [ ] La existencia de Initiative en el dispatcher usa el Workspace efectivo.
- [ ] Un update cross-Workspace sin relaciones devuelve `NOT_FOUND` para keys limitadas y no limitadas.
- [ ] La operación no modifica la Initiative ajena.
- [ ] Existe una regresión con dos Workspaces y una Initiative sin relaciones.
- [ ] SQLite y PostgreSQL conservan errores de aislamiento consistentes cuando la infraestructura PostgreSQL esté disponible.

## Relación

Hallazgo separado de PRB-587 y PRB-589: cubre el error de dominio para una Initiative ajena vacía, no referencias cross-Workspace de Projects.
