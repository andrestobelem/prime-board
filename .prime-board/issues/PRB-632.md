# PostgreSQL: revalidar grants de Workspace de API keys en mutaciones de planning

Created by admin.

## Hallazgo

La revisión de PRB-618 observó que `readPostgresAuthScope` relee la key y sus Team limits, pero no verifica dentro de la transacción `api_key_workspaces`/grant efectivo de Workspace. Una revocación concurrente puede dejar una autorización basada en un grant obsoleto si la mutación solo valida el scope de Teams.

## Comportamiento esperado

Las mutaciones PG que usan AuthScopeContext deben revalidar dentro de la misma transacción la key, Workspace grant/Membership y Team limits que sustentan la autorización. Una revocación o cambio concurrente debe rechazar sin escritura.

## Criterios de aceptación

- [ ] `readPostgresAuthScope` o el helper de dominio verifica key activa, Workspace grant y Membership dentro de la transacción.
- [ ] Cambios concurrentes de `api_key_workspaces`/grant producen rechazo y no-write.
- [ ] Admin/unrestricted, key limitada y ausencia de grant conservan sus errores/contratos.
- [ ] SQLite mantiene garantía equivalente.
- [ ] Tests PG/SQLite, typecheck, Prettier y diff-check pasan o documentan brechas.
