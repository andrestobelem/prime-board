# CLI/MCP: borrar relaciones duplicate-of desde cualquiera de sus extremos

Created by admin.

## Hallazgo reproducible

La API devuelve el tipo inverso `DUPLICATED_BY`, pero los clientes solo buscan `DUPLICATE_OF` al borrar:

1. Crear relación `issueRelationCreate(A, B, DUPLICATE_OF)`.
2. Desde `B`, GraphQL muestra `relations: [{ type: DUPLICATED_BY, relatedIssue: A }]`.
3. Ejecutar `pb issue unlink B --duplicate-of A --json`: termina con código 1, `No duplicate of relation between B and A`, y la relación permanece.
4. El tool MCP `unlink_issues` presenta el mismo error para `type: duplicate_of`.

Evidencia: `apps/cli/src/commands/issue.ts:39-48,275-303` y `apps/mcp/src/server.ts:766+` comparan únicamente `DUPLICATE_OF`; PRB-179 cubrió la superficie base pero no el extremo inverso.

## Comportamiento esperado

`unlink` debe aceptar una relación duplicate-of desde cualquiera de sus extremos, normalizar la inversa y borrar una única fila canónica.

## Criterios de aceptación

- CLI y MCP borran `duplicate_of` y `duplicated_by` desde ambos lados.
- Las relaciones `blocks/blocked_by` y `related` conservan su semántica actual.
- El comando devuelve error solo cuando no existe relación real.
- Agregar pruebas e2e de creación, vista inversa y borrado en ambas direcciones.
