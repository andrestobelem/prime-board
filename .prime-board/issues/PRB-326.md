# CLI/MCP: completar paginación y filtros del listado de issues

Created by admin.

## Hallazgo reproducible

GraphQL acepta `issues(filter, first, after, orderBy)` y `IssueFilter` incluye creator, milestone, cycle, parent, labels, `includeArchived` y combinaciones `and/or`. `apps/cli/src/commands/issue.ts` solo expone team/state/assignee/priority/project/search/unblocked/first; `apps/mcp/src/server.ts` ofrece un subconjunto aún menor. Ninguno envía `after`, `orderBy` o `includeArchived`, ni filtros de cycle/milestone/labels/parent/creator/compuestos. `pb issue list --after opaque` reproduce rc=2: `Unknown option '--after'`; la API devuelve `hasNextPage:true` y `endCursor`, pero los clientes no pueden continuar.

## Comportamiento esperado

CLI y MCP deben poder recorrer resultados completos y expresar los filtros soportados por la API, o declarar/documentar claramente un contrato reducido.

## Criterios de aceptación

- `pb issue list` acepta cursor de continuación, orden y archived; una ejecución sobre más de 50 issues permite recuperar la segunda página.
- `list_issues` MCP ofrece la misma paginación y filtros o un contrato documentado equivalente.
- Se cubren cycle, milestone, labels, parent, creator, compuestos y `includeArchived` con tests.
- Se mantienen `pageInfo`/errores consistentes y no se repiten ni pierden issues.

## Duplicados/relación

PRB-286 cubre paginación UI y PRB-260 la auditoría CLI/MCP; no cubren la API funcional faltante en estos clientes.
