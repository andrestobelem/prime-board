# Definir el contrato idempotente de migración desde Linear

## Objetivo

Especificar cómo se identifica una entidad ya migrada y cómo se repite la migración sin duplicar ni sobrescribir silenciosamente datos.

## Alcance

Definir el mapa Linear → prime-board para workspace, teams, actores, workflow states, labels, proyectos, milestones e issues; la política para conservar fechas y autores; y el formato del reporte de migración.

## Aceptación

* Cada entidad tiene una clave de correspondencia estable.
* Se documentan conflictos de nombres, estados y actores.
* El contrato distingue datos importados, datos locales y datos no representables.
* Incluye modo `dry-run` y códigos de salida para automatización.
