# Web: refrescar los Comments de una Issue después de crearlos

Created by admin.

## Hallazgo reproducible

En la vista web de una Issue, al enviar un Comment válido, la mutación termina pero el Comment nuevo no aparece de inmediato. La lista solo muestra el contenido después de recargar la página o volver a abrir la Issue.

## Comportamiento esperado

Después de crear un Comment, la vista debe mostrarlo sin recarga manual. El formulario debe conservar el comportamiento actual para errores y no duplicar el Comment si la respuesta o una actualización llegan más de una vez.

## Criterios de aceptación

- [ ] Crear un Comment desde la vista web actualiza la lista visible de la Issue en la misma interacción.
- [ ] El Comment aparece con su cuerpo, Actor y fecha devueltos por la API.
- [ ] Un error de `commentCreate` no agrega contenido optimista falso ni bloquea el formulario.
- [ ] No se duplican Comments al combinar la respuesta de la mutación con una recarga o evento posterior.
- [ ] Existe una prueba de regresión en el seam de la UI.
- [ ] La corrección referencia este Issue en el commit y en la evidencia final.
