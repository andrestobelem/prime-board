# Migraciones: resolver colisión SQLite 0032 entre Notifications y Views

Created by admin.

## Hallazgo

PRB-386 y PRB-390 fueron desarrollados sobre bases distintas y ambos agregan una migración SQLite `0032`, pero con contenido diferente:

- PRB-386: `0032_notification_preferences.sql`.
- PRB-390: `0032_views_preferences.sql`.

Al integrar ambos branches, el migrator puede omitir una migración, aplicar el contenido equivocado o dejar el upgrade no determinista.

## Comportamiento esperado

Cada migración tiene una versión/nombre único y un orden monotónico en la rama canónica. Una base nueva y una base existente que ya aplicó PRB-386 deben aplicar también PRB-390 sin perder datos ni saltar migraciones.

## Criterios de aceptación

- [ ] Se elimina la colisión sin modificar el contrato funcional de Notifications ni Views.
- [ ] El orden y los identificadores de migración SQLite son únicos y compatibles con bases existentes.
- [ ] Fresh database aplica ambas migraciones y crea todas las tablas/índices esperados.
- [ ] Upgrade desde una base con PRB-386 `0032_notification_preferences` aplica Views de forma segura.
- [ ] Tests cubren migración repetida, upgrade, rollback/fallo y ausencia de pérdida de datos.
- [ ] La numeración/relación de migraciones PostgreSQL también se verifica.
- [ ] Docs, Prettier y diff-check pasan.

## Trazabilidad

Colisión detectada al revisar PRB-390 contra la entrega ya cerrada de PRB-386. No renumerar ni editar migraciones hasta registrar este Issue.
