# Replica: evitar ENOBUFS con event log grande

Created by admin.

## Hallazgo reproducible

Con la instancia aislada activa, ejecutar:

```bash
pb issue update PRB-564 --state completed --json
```

El CLI devuelve:

```text
API error: spawnSync git ENOBUFS (stdout or stderr buffer reached maxBuffer size limit)
```

La mutación sí queda aplicada en el board (`PRB-564` pasa a `Done`). El error aparece durante la sincronización del Repository Replica porque `.prime-board/log/events.jsonl` mide aproximadamente `2,084,434` bytes. `apps/server/src/export/issue-event-pipeline.ts` usa `spawnSync` para leer el event log completo mediante `git show` sin un límite adecuado o streaming.

## Comportamiento esperado

Una mutación con un event log grande debe devolver una respuesta exitosa y consistente, o fallar antes de aplicar el cambio con un error recuperable. El CLI no debe informar un fallo cuando el estado durable ya cambió.

## Criterios de aceptación

- [ ] Las mutaciones funcionan cuando el event log supera el límite por defecto de `spawnSync`.
- [ ] La respuesta del API y el estado de la réplica reflejan el mismo resultado.
- [ ] Un fallo de sincronización no deja una mutación aplicada con respuesta de error ambiguo.
- [ ] Hay una regresión con un event log mayor que el límite actual.
- [ ] La solución conserva el orden append/commit/projection y no carga secretos.
- [ ] Pasan los tests focales, typecheck, Prettier y `git diff --check`.

## Evidencia

- Comando: `pb issue update PRB-564 --state completed --json`.
- Resultado observado: `ENOBUFS`; una consulta posterior muestra `PRB-564` en `Done`.
- Archivo observado: `.prime-board/log/events.jsonl` (`2,084,434` bytes).

## Fuera de alcance

No cambiar el modelo del event log ni migrar el almacenamiento en este ticket.
