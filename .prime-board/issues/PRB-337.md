# UI: administrar memberships de teams desde el roster

Created by admin.

## Hallazgo reproducible

GraphQL expone `teamMembershipCreate/Delete` y `teamMemberships`, pero no aparecen esas mutaciones en `apps/web/src`. `MembersView.tsx:30-79` administra actors y API keys; `TeamSettingsView.tsx:15` solo lee memberships. La matriz vigente `docs/alcance-mvp.md` marca teams, actores, memberships y API keys como soportados en UI. No existe pantalla/acción para agregar, cambiar o quitar miembros de un team.

## Comportamiento esperado

Owners/managers autorizados deben poder consultar y administrar el roster de cada team desde UI; usuarios sin permiso deben verlo de forma coherente con ACL.

## Criterios de aceptación

- Se muestra el roster con actor, rol/membership y estado relevante.
- Se puede agregar/quitar membership (y modificar los campos que la API soporte) con confirmación y estados loading/error.
- La UI oculta/deshabilita acciones para no autorizados y refleja cambios al recargar.
- Tests cubren owner autorizado, member sin permiso, outsider y el último miembro si hay una invariante.
- La matriz/documentación coincide con la capacidad real.

## Duplicados/relación

PRB-221/235 cubren modelo/API/ACL de membership y actores; no implementan el roster ni sus controles en UI.
