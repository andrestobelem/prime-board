# Validar paridad, concurrencia y restauración

Created by admin.

## What to build
Demostrar que el replay del Repository Source reproduce el estado y comportamiento de PostgreSQL antes del cutover.

## Acceptance criteria
- [ ] Replay desde cero y replay incremental producen el mismo estado lógico, snapshots y metadata.
- [ ] Conteos, identifiers, foreign keys, timestamps, GraphQL, export y búsqueda coinciden con el estado legado esperado.
- [ ] Se prueban idempotencia, checkpoints, merge union, conflicto del mismo campo, numeración concurrente, invitaciones, scopes, relaciones y webhooks.
- [ ] `pg_dump`/`pg_restore` sobre una instancia limpia pasa smoke tests sin convertirse en fuente de dominio.
- [ ] Health, pool, cierre y migraciones concurrentes fallan de forma segura y dejan evidencia.
