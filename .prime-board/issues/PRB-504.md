# Teams: la creación de un Team no propaga el Workspace en SQLite

Created by admin.

## Hallazgo

Al integrar `PRB-472`, `bun run typecheck` detectó que `apps/server/src/domain/teams.ts` sigue llamando `seedTeamWorkflow(db, id)` con la firma antigua. El mismo dominio:

- inserta `teams` sin `workspace_id`;
- comprueba `Team.key` con `SELECT id FROM teams WHERE key = ?1` global;
- crea `team_memberships` sin `workspace_id`.

El resolver sí tiene `context.workspace.workspaceId`, pero no lo pasa al dominio.

## Comportamiento esperado

`teamCreate` debe crear el Team, sus Workflow States y su owner dentro del Workspace de la request. La misma key debe poder existir en otro Workspace y debe rechazarse solo dentro del Workspace actual.

## Criterios de aceptación

- [ ] El resolver propaga el Workspace actual al dominio SQLite.
- [ ] Todas las filas creadas incluyen el Workspace correcto.
- [ ] La validación de key queda scoped al Workspace.
- [ ] Hay regresión de creación en un segundo Workspace.
- [ ] `bun run typecheck` pasa.
