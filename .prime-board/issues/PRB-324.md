# CLI/MCP: exponer archive de issues y mutaciones administrativas GraphQL

Created by admin.

## Hallazgo reproducible

La introspección/SDL expone `issueArchive` y mutaciones administrativas `teamCreate/Update`, `teamMembershipCreate/Delete`, `actorCreate/Update`, `apiKeyCreate/Delete`, `workflowStateCreate/Update/Delete` y `labelCreate/Update/Delete`, pero no hay operaciones equivalentes en `apps/cli/src` ni tools MCP en `apps/mcp/src/server.ts`. `bun apps/cli/src/index.ts issue archive PRB-999` termina con rc=2/Usage sin hacer request, mientras GraphQL sí registra `issueArchive`.

La matriz vigente (`docs/alcance-mvp.md:28-29`) declara soporte de teams, actores, memberships, workflow y labels en las superficies, y `docs/guia-agentes.md:45` afirma paridad total.

## Comportamiento esperado

Los agentes deben poder ejecutar las operaciones soportadas por la API desde CLI y MCP, con la misma autorización, errores y semántica de respuesta. Si alguna mutación es deliberadamente GraphQL-only por bootstrap, debe quedar fuera de la matriz y documentada como excepción; `issueArchive` debe tener una interfaz de agente.

## Criterios de aceptación

- Inventario/introspection contract identifica cada operación GraphQL y su cobertura CLI/MCP o excepción documentada.
- `pb issue archive` y una tool MCP equivalente ejecutan archive con tests de éxito, idempotencia y permisos.
- Las operaciones de teams, memberships, actors, API keys, workflow states y labels tienen comandos/tools equivalentes o una decisión explícita y documentada de exclusión.
- La matriz y la documentación dejan de afirmar paridad donde no exista; pruebas e2e cubren las superficies implementadas.
