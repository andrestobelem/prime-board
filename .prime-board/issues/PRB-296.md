# CLI/MCP: recorrer paginación y orden de list_issues

Created by admin.

## Hallazgo reproducible

Los clientes para agentes devuelven `pageInfo.endCursor` pero no permiten usarlo:

- `pb issue list --first 1 --json` incluye `hasNextPage/endCursor`, pero `pb issue list --after <cursor>` termina con error de uso porque `apps/cli/src/commands/issue.ts:25-91` no registra ni envía `after` (tampoco expone `orderBy`).
- El tool MCP `list_issues` (`apps/mcp/src/server.ts:107-163`) solo acepta `limit`; también devuelve cursor sin input para continuar.

Con más de 50/250 issues, un agente no puede obtener una cola completa ni reproducir el orden solicitado sin GraphQL directo.

## Comportamiento esperado

CLI y MCP deben ofrecer paginación cursor-based y orden equivalente a GraphQL, o una abstracción `list all` que consuma todas las páginas sin truncar silenciosamente.

## Criterios de aceptación

- CLI acepta `--after` y `--order-by` en `issue list`, mantiene `--json` y devuelve `pageInfo` estable.
- MCP `list_issues` acepta cursor y orden, con límites validados.
- Documentar cómo recorrer páginas y cubrir filtros combinados en tests de contrato.
- La salida no pierde issues ni duplica filas al avanzar de página.
