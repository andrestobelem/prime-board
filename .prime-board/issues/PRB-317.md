# API: impedir ciclos de parent con más de 100 niveles

Created by admin.

## Hallazgo reproducible

`apps/server/src/domain/issues.ts:114-132` implementa `validateParent` con un límite fijo de `depth < 100` y termina sin error al alcanzar ese límite. La reproducción aislada `scratchpad/audit-parent.ts` crea una cadena de 105 issues, intenta asignar el último como parent del primero y obtiene `issueUpdate(...): success:true`; la consulta SQL confirma que se persiste el ciclo. La cobertura de `apps/server/src/graphql/issues.test.ts` solo cubre un ciclo corto/directo.

## Comportamiento esperado

Toda asignación de parent debe rechazar ciclos, sin un límite arbitrario silencioso, y conservar la relación anterior cuando la operación falla. Si se necesita un límite operativo, excederlo debe devolver un error explícito y no persistir la relación.

## Criterios de aceptación

- Una regresión con una cadena de más de 100 niveles rechaza el cierre del ciclo y deja intacta la relación previa.
- Se conservan las validaciones para ciclos directos y cortos.
- La respuesta GraphQL usa un error de validación estable y no deja datos cíclicos en la base.
- Se actualizan los tests de dominio/GraphQL y pasan junto con la suite existente.
