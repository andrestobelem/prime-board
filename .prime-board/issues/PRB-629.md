# Migrator: exigir FK compuesta de Workspace y Team en saved_views

Created by admin.

## Hallazgo

La re-revisión de PRB-619 encontró que `hasSavedViewsForeignKey` comprueba cada fila de `PRAGMA foreign_key_list(saved_views)` por separado. Acepta una tabla con FKs independientes para `workspace_id -> teams.workspace_id` y `team_id -> teams.id`, aunque el esquema canónico requiere una FK compuesta `(workspace_id, team_id) -> teams(workspace_id, id)`.

Se reprodujo con una DB v32 que tenía las 13 columnas, PK e índices, pero tres FKs independientes. El preflight aceptó el esquema y marcó 0033. Ese esquema no garantiza que el Team pertenezca al Workspace correcto.

## Comportamiento esperado

El preflight debe comprobar la identidad estructural de cada FK compuesta: mismo `PRAGMA foreign_key_list.id`, columnas y orden esperados, tabla/columnas referenciadas y acción. Un esquema con FKs separadas o incompletas debe fallar antes de DDL, datos o marker.

## Criterios de aceptación

- [ ] Una tabla con FKs independientes que imitan la FK compuesta falla cerrada y no marca 0033.
- [ ] La FK compuesta canónica pasa y permite aplicar 0033.
- [ ] El fallo deja DDL, datos, tablas temporales y `_migrations` sin cambios, y el reintento repite el error.
- [ ] La corrección conserva las validaciones de PRB-619 para PK, índices, unicidad, filas y referencias cross-Workspace.
- [ ] Hay regresiones SQLite reproducibles sin casts `as` nuevos; typecheck, Prettier y diff-check pasan o documentan brechas preexistentes.

## Trazabilidad

Hallazgo posterior al PASS de PRB-619. Corregir antes de integrar PRB-620/PRB-615.
