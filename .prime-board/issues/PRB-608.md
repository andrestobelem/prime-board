# PostgreSQL: encapsular relaciones de planning en dominio

Created by admin.

## Hallazgo

La ruta PostgreSQL de `projectDependencyCreate` y `projectDependencyDelete` escribe/borra `project_dependencies` directamente desde `apps/server/src/graphql/project-resolvers.ts`. La ruta SQLite usa dominio, pero la ruta PostgreSQL no tiene un helper equivalente.

## Comportamiento esperado

Las mutaciones GraphQL deben delegar la persistencia PostgreSQL de Projects e Initiatives en funciones de dominio/proyección. El resolver solo coordina contexto, errores y eventos. El dominio debe validar tipos, referencias, self-dependency, transacción y retorno estable.

## Criterios de aceptación

- [ ] `projectDependencyCreate/Delete` usan helpers de `domain/postgres-projects.ts`.
- [ ] Las escrituras de planning PostgreSQL no quedan duplicadas en resolvers.
- [ ] El helper es transaccional, valida referencias del Workspace y conserva `blocks|related`.
- [ ] Regresiones cubren éxito, self-dependency, referencia ausente y rollback.
- [ ] SQLite/PostgreSQL mantienen el mismo contrato GraphQL.

## Evidencia

HEAD `fd8d9663`, ruta `apps/server/src/graphql/project-resolvers.ts:714-786`. Hallazgo independiente detectado durante PRB-391; no corregir desde otro Issue.
