# Endurecer staging concurrente del event log canónico

Created by admin.

## Objetivo

Preservar cambios staged concurrentes sobre `.prime-board/log/events.jsonl` durante el commit Git del event log canónico.

## Evidencia

La revisión independiente de PRB-445 en `70c7ce6` reprodujo una ventana TOCTOU entre la última lectura de `git ls-files --stage` y `git update-index`. Un `git add` concurrente sobre `events.jsonl` puede quedar como cambio no staged después de la actualización del índice. El contenido permanece en el working tree, pero se pierde el estado staged ajeno.

## Criterios de aceptación

- `createGitCommitter` no reemplaza ni descarta un índice staged concurrente para `events.jsonl`.
- La sincronización del índice usa una operación protegida y conserva entradas ajenas.
- Una carrera entre `git add` y la sincronización falla cerrado o conserva el contenido y su estado staged.
- Hay una regresión reproducible para esta carrera.
- Se ejecutan tests focales, typecheck, Prettier y `git diff --check`.
