# Ops: DB local quedó en migración 5; features 6–13 no están en el índice vivo

Created by admin.

## Evidencia

`~/.prime-board/prime-board.db` tiene `_migrations` 1–5 únicamente. El código ya define 0006–0013 (`saved_views`, `cycles`, `reviews`, `initiatives`, `project_updates`, `inbox_receipts`, `initiative_owner`, etc.).

En `.prime-board/meta/` del repo **faltan** los JSON nuevos (`saved-views.json`, `cycles.json`, `reviews.json`, `initiatives.json`, `project-updates.json`) aunque el exporter ya los escribe: el índice vivo nunca tuvo esas tablas, así que no hay datos que proyectar.

El server en `:3333` sigue corriendo contra esa DB sin migrar.

## Esperado

- Reiniciar el server para aplicar migraciones.
- Tras writes reales, el export debe materializar los meta JSON (aunque sea `[]`).
- Verificar que GraphQL de vistas/ciclos/etc. responde contra la DB migrada.

## Criterios

- `_migrations` incluye 6–13 en la DB operativa.
- `meta/*.json` de features nuevas aparecen en el repo tras un export.
- Smoke de una mutación por feature (o al menos que el schema no falle al consultar).
