# Frontend: separar la navegación de Workspace y Teams en el shell

Created by admin.

## Hallazgo reproducible

Las capturas de referencia muestran dos niveles distintos de navegación: recursos del `Workspace` y recursos de cada `Team`. La UI actual mezcla parte de ambos niveles y no ofrece la misma estructura.

## Evidencia

- Referencia: el menú superior identifica el workspace `andrestobelem`; debajo aparecen los teams `pobrespandas` y `andrestobelem`.
- Referencia: cada team expone `Home`, `Issues`, `Projects` y `Views`; el workspace expone `Inbox`, `My issues`, `Reviews`, recursos globales y `Views`.
- Código actual: `apps/web/src/components/Sidebar.tsx` renderiza `Teams`, `Inbox`, `My issues`, `Reviews` e `Initiatives` bajo Workspace, y luego `Triage`, `Issues`, `Projects` y `Cycles` por team. No hay navegación `Home` por team ni separación visible de Views globales y Views de team.
- La API ya distingue `Workspace`, `Team`, `Project` y `SavedView.scope`, por lo que este ticket no requiere cambiar el modelo de datos existente.

## Comportamiento esperado

El shell debe hacer explícita la jerarquía `Workspace → Teams` sin duplicar ni atribuir recursos al scope equivocado. El menú del workspace debe poder incluir recursos globales; cada team debe agrupar sus propias rutas y vistas.

## Criterios de aceptación

- [ ] El nombre/menu del workspace se distingue visualmente de la sección `Your teams`.
- [ ] Los recursos workspace-scoped y team-scoped tienen entradas y estados activos correctos.
- [ ] Cada team tiene navegación consistente para Home/Issues/Projects/Views; los ciclos y el triage conservan sus rutas sin mezclarse con el workspace.
- [ ] Projects y Views no aparecen duplicados ni bajo un scope incorrecto.
- [ ] El shell mantiene loading/error/empty states y navegación responsive.
- [ ] Hay pruebas de componentes o de rutas para al menos dos teams y vistas de scopes distintos.
