# Teams: implementar borrado seguro y definitivo

Created by admin.

## Objetivo

Implementar el borrado seguro de un Team cuando ya no deba conservarse en el Workspace.

## Contexto

Actualmente prime-board no expone `team delete`. El archivado reversible se sigue por separado en PRB-372; este ticket cubre la eliminación definitiva y sus garantías de seguridad.

## Alcance

- Definir y documentar las precondiciones para borrar un Team.
- Exigir autorización de Workspace Admin y una confirmación explícita/no ambigua.
- Impedir el borrado accidental de Teams con Issues, Projects, Cycles, Workflow States, Activities, memberships, labels u otros recursos dependientes, o definir una política transaccional explícita para cada dependencia.
- Exponer la operación mediante GraphQL, CLI (`pb team delete`) y MCP.
- Actualizar UI y documentación con advertencias claras y sin ofrecer borrado como sustituto silencioso del archivado.
- Registrar la operación administrativa y mantener consistencia de la Repository Replica.

## Criterios de aceptación

- Solo un Workspace Admin puede solicitar el borrado.
- La API rechaza por defecto Teams con dependencias y devuelve un error accionable; no hay borrado parcial.
- La operación, cuando cumple las precondiciones, es atómica y no deja referencias huérfanas.
- CLI, MCP y UI requieren confirmación explícita y muestran el impacto antes de ejecutar.
- Hay regresiones para autorización, precondiciones, atomicidad, referencias y auditoría.
- La documentación diferencia claramente `archive` (reversible) de `delete` (definitivo).
