# Integración: PRB-472 y PRB-473 colisionan en la migración 0025

Created by admin.

## Hallazgo

Las dos Issues de datos del ciclo se implementaron en paralelo y ambas usan la migración SQLite `0025`.

## Evidencia

- `scout/prb-472` (`58fbcc6`) agrega `apps/server/src/db/migrations/0025_workspace_constraints.sql` y registra `{ version: 25, name: "workspace_constraints" }`.
- `builder/prb-473` (`5e50b80`) agrega `apps/server/src/db/migrations/0025_api_key_workspaces.sql` y registra `{ version: 25, name: "api_key_workspaces" }`.
- Ambos modifican `apps/server/src/db/database.ts` en el mismo import y en la misma entrada de `MIGRATIONS`.
- Cada branch pasa sus pruebas aisladas, pero no se pueden integrar juntos sin resolver nombre, versión y orden de migración.

## Comportamiento esperado

Las migraciones de agentes paralelos deben tener versiones únicas y una integración determinista. La combinación debe conservar ambos cambios y ejecutar los backfills en el orden correcto.

## Criterios de aceptación

- [ ] La integración contiene las dos migraciones sin perder constraints ni grants.
- [ ] Cada migración tiene un número y nombre únicos, con orden explícito.
- [ ] Una base legacy puede migrar por ambas etapas y `migrate` sigue siendo idempotente.
- [ ] Hay una prueba de integración que combina las dos ramas o reproduce la colisión.
- [ ] La resolución no modifica credenciales ni datos de otros Workspaces.
