# Auth: resolver WorkspaceContext, grants y selector

Created by admin.

## Objetivo
Resolver Actor, credencial, Membership y Workspace efectivo antes de ejecutar cualquier operación.

## Criterios de aceptación
- El modo single-workspace conserva compatibilidad sin selector cuando la key tiene un único grant o un default válido.
- Una key válida para A no puede leer ni mutar B, aunque el request envíe un ID conocido de B.
- Un selector inexistente, no concedido o ambiguo devuelve `WORKSPACE_REQUIRED` o `UNAUTHORIZED` sin filtrar existencia.
- Scopes y límites de Team se evalúan dentro del grant y nunca amplían la Membership.
- Un resolver no puede confiar en un `workspaceId` recibido como input.

## Seam de validación
`resolveAuth`, `WorkspaceContext`, headers GraphQL, API-key grants y tests negativos de autorización.

## Dependencias
Requiere `PRB-412` completo.
