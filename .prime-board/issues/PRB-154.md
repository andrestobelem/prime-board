# XSS: el markdown de issues y comentarios no se sanitiza

🔴 **Vulnerabilidad encontrada en QA exploratorio.** El markdown de descripciones y comentarios se renderiza con `marked` + `dangerouslySetInnerHTML` **sin sanitizar**, y `marked` deja pasar HTML crudo por diseño.

**Reproducción (verificada con Playwright en un board de prueba):**
1. Crear un issue con descripción: `Hola <img src=x onerror="document.title='PWNED'">`
2. Abrir el detalle en la UI → el `onerror` **se ejecuta** (`document.title` pasó a `PWNED`).
3. Un comentario con `<a href="javascript:alert(1)">` conserva el href `javascript:`.

*(El `<script>` inline no corre porque el navegador no ejecuta scripts insertados por `innerHTML`, pero los handlers `on*` y los href `javascript:` sí.)*

**Por qué importa acá:** en prime-board el contenido lo escriben **agentes**, que a su vez procesan input externo (issues importados, webhooks, páginas que leen). Es una vía directa de prompt-injection a XSS: el atacante roba la API key del `localStorage` del humano que abre el ticket.

**Arreglo propuesto:** sanitizar el HTML resultante antes de inyectarlo — `DOMPurify` sobre la salida de `marked`, o `marked` con un renderer que escape HTML crudo. Cubrir descripción y comentarios (`Markdown` en `IssueView`). Agregar test que verifique que `onerror` y `javascript:` no sobreviven.

*Encontrado en la sesión de QA exploratorio.*
