# Migrator: no omitir 0033 cuando falta saved_views

Created by admin.

## Hallazgo

La revisión de PRB-615 encontró que `apps/server/src/db/database.ts:300-306` hace `continue` cuando falta `saved_views`. En ese caso el runner devuelve éxito con `migration_count=31` y `version33=null`; las corridas siguientes repiten la omisión.

## Comportamiento esperado

El migrator no debe omitir silenciosamente una migración. Si `0033` debe crear o transformar Views, debe aplicarse; si el esquema base es incompatible, debe fallar antes de marcar éxito con un error de recuperación explícito.

## Criterios de aceptación

- [ ] Una base en versiones 1–30 sin `saved_views` no omite `0033` silenciosamente.
- [ ] La ruta compatible crea/aplica la tabla, índices y metadata esperados, o la ruta incompatible falla cerrada sin marcar la migración aplicada.
- [ ] La aplicación repetida es idempotente y registra el resultado correcto en `_migrations`.
- [ ] Fresh DB, upgrade, fallo/rollback y schema incompatible tienen regresiones reproducibles.
- [ ] El cambio no altera Notifications `0032` ni el contrato de Views.
- [ ] Typecheck, Prettier y diff-check pasan o documentan brechas preexistentes.

## Trazabilidad

Hallazgo de la revisión independiente de PRB-615. No corregirlo desde el branch original de PRB-390.
