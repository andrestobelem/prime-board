# GraphQL: conservar variables de fragments anidados en fallback legacy

Created by Builder.

## Hallazgo de revisión de PRB-580

`variablesInSelectionSet()` visita las variables del `SelectionSet` actual, pero solo sigue `FragmentSpread` cuando es una selección directa. No recorre los `Field` ni los `InlineFragment` que contienen fragments.

**Reproducción conceptual:**

```graphql
query Q($a: Boolean!, $b: Boolean!, $c: Boolean!) {
  viewer { ...A @include(if: $a) }
}
fragment A on Viewer @include(if: $b) { ...B }
fragment B on Viewer { id @include(if: $c) }
```

El fallback puede conservar `$a` pero eliminar `$b` y `$c` de la definición de `Q`, aunque siguen siendo usados por directivas de fragments alcanzables. El resultado falla validación con variables no definidas.

## Comportamiento esperado

La limpieza de variables debe recorrer fields, inline fragments, spreads y directivas de fragments alcanzables. Un documento legacy transformado no debe declarar menos variables de las que usa.

## Criterios de aceptación

- [ ] La colección de variables recorre fragments anidados dentro de fields e inline fragments.
- [ ] Conserva variables usadas por directivas de spreads, fragments y campos alcanzables.
- [ ] El documento transformado pasa parseo y validación sin variables no definidas.
- [ ] Existe regresión para una cadena nested de fragments.
- [ ] Queries, mutations y subscriptions mantienen sus correcciones anteriores.
