# GraphQL: aplicar WorkspaceContext antes de autorizar mutaciones

Created by admin.

## Hallazgo de revisión de PRB-476

Algunas mutaciones SQLite llaman `assertCanManageTeam(context.db, viewer, teamId)` antes de resolver el Team con el Workspace efectivo. `auth/permissions.ts` usa un lookup sin Workspace en esa ruta.

**Reproducción:**

1. Crear actor miembro en Workspace B.
2. Seleccionar Workspace B.
3. Enviar `teamUpdate(id=teamA)`, `labelCreate(teamId=teamA)` o `workflowStateCreate(teamId=teamA)`.

La respuesta es `UNAUTHORIZED: Team owner permission is required` en lugar de `NOT_FOUND`. Un admin de B llega al guard y recibe `NOT_FOUND`, por lo que la diferencia expone un side-channel y rompe el contrato fail-closed.

## Criterios de aceptación

- [ ] Las mutaciones resuelven primero el recurso con el Workspace efectivo.
- [ ] Un ID de otro Workspace devuelve `NOT_FOUND` de forma consistente para miembros y admins.
- [ ] La autorización se ejecuta solo después del guard scoped.
- [ ] La operación válida en el Workspace activo conserva sus permisos y respuesta.
- [ ] Hay regresiones para actor miembro y admin con dos Workspaces.
