# Migraciones: resolver colisión 0031/0012 entre Workflow y Planning

Created by admin.

## Hallazgo

PRB-383/601 y PRB-391/606 usan el mismo número de migración para cambios distintos: SQLite `0031_workflow_settings.sql` frente a `0031_planning_settings.sql`, y PostgreSQL `0012_workflow_settings.sql` frente a `0012_planning_settings.sql`. Cada registro de migración admite una sola versión. Al integrar ambas ramas, una migración queda omitida o el registro resulta incompatible.

Además, PRB-383/601 modifica `apps/server/src/db/postgres/0001_baseline.sql`. Una base PostgreSQL existente conserva el checksum del baseline anterior y el migrator falla con `CHECKSUM_MISMATCH` antes de aplicar la migración nueva.

## Comportamiento esperado

Las migraciones nuevas deben tener versiones únicas y el baseline existente debe permanecer inmutable. Una instalación existente debe actualizarse sin perder columnas/tablas de ninguna de las dos funcionalidades.

## Evidencia

- PRB-601: `0031_workflow_settings.sql`, `0012_workflow_settings.sql` y cambio de `0001_baseline.sql`.
- PRB-606: `0031_planning_settings.sql` y `0012_planning_settings.sql`.
- `database.ts` y `postgres/migrator.ts` registran una sola entrada por versión.

## Aceptación

- [ ] Renumerar o combinar las migraciones SQLite y PostgreSQL sin omitir cambios.
- [ ] Restaurar la inmutabilidad del baseline y mover sus cambios a una migración nueva.
- [ ] Probar upgrade desde una base existente y una instalación nueva.
- [ ] Verificar rollback y checksums en SQLite/PostgreSQL.
