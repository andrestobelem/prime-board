# MCP: permitir limpiar assignee, project y milestone de una issue

Created by admin.

## Hallazgo reproducible

GraphQL `IssueUpdateInput` y CLI permiten limpiar campos nullable (`assigneeId:null`, `projectId:null`, `milestoneId:null`), pero MCP no:

- `save_issue` declara `assignee`, `project` y `milestone` como strings no-null y siempre resuelve/envía un ID.
- Solo `parent` tiene una opción explícita `null`.

Un agente MCP puede asignar esos campos, pero no desasignarlos ni corregir una asignación sin GraphQL/CLI.

Evidencia: `apps/mcp/src/server.ts` schema/handler de `save_issue` y `apps/mcp/src/resolve.ts:resolveActor`; el schema GraphQL declara campos nullable y el CLI ya soporta `none` para assignee/project/milestone.

## Comportamiento esperado

La tool MCP debe representar explícitamente “sin valor” y distinguir campo omitido (no cambiar) de null (limpiar), manteniendo validación y autorización.

## Criterios de aceptación

- `assignee: null`, `project: null` y `milestone: null` limpian el campo en create/update según corresponda.
- Omitir el campo conserva el valor actual.
- IDs/nombres inválidos siguen produciendo errores estables.
- Agregar tests de contrato para asignar, limpiar y round-trip.
