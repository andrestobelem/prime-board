# Boundary local de seguridad y credenciales

Created by admin.

## Objetivo
Limitar la exposición de red y separar las credenciales del package, los settings de Prime Agent y la Repository Replica.

## Modos de autenticación
- El modo predeterminado `api-key` limita GraphQL y MCP a un bearer válido.
- El modo `local` solo se activa de forma explícita con `PRIME_BOARD_AUTH_MODE=local`; en ese modo la instancia debe escuchar en `127.0.0.1` y permite el uso local sin API key.
- `/health` es anónimo en ambos modos.
- El modo `api-key` conserva el rechazo de solicitudes sin credenciales. El modo `local` no cambia el comportamiento de una instancia remota ni permite un host no loopback.

## Criterios de aceptación
- El bind predeterminado es `127.0.0.1`; cualquier override de host es explícito y está documentado.
- `/graphql` permite consultas y mutaciones sin `Authorization` solo en el modo `local` explícito. El transporte MCP siempre exige un bearer que envía el cliente, incluso cuando usa una instancia local.
- Bootstrap, API keys y secretos se almacenan fuera del package y de `.prime-board/`, con permisos `0600` cuando el sistema lo permite.
- API keys y secretos no aparecen en logs, settings de Prime Agent ni exports.
- Los paths de proyecto se pasan como argumentos, sin interpolación en shell.
- Hay regresiones para los modos `api-key` y `local`, el bind loopback y la ausencia de secretos.

## Seam de validación
Servidor HTTP, GraphQL/MCP, filesystem de credenciales, logs y export.
