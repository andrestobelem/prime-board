# Security: evaluar login methods, sesiones, SSO/SCIM e IP restrictions

Created by admin.

## Objetivo
Registrar y diseñar la superficie de seguridad avanzada: métodos de login, sesiones, passkeys, SAML, SCIM, dominios y allowlists IP. Implementar solo si el modelo de despliegue lo requiere.

## Contexto
Gap identificado en `docs/research/linear-settings-parity.md` (PRB-376), categoría P3.

## Criterios de aceptación
- La decisión de alcance queda documentada; cualquier capacidad implementada tiene pruebas de revocación y no debilita el modelo local-first.
- La implementación debe conservar el modelo local-first, single-tenant y API-first de prime-board.
- Agregar regresiones y evidencia en este issue antes de cerrarlo.

## Revalidación contra Linear actual (2026-08-22)

### Ajustes de alcance

- Separar Security & Access de los controles Enterprise de identidad.
- Security & Access incluye sesiones revocables, passkeys, API keys y aplicaciones autorizadas.
- Las restricciones de login son Business/Enterprise. SAML e IP restrictions son Enterprise. SCIM es Enterprise y desplaza el provisioning al IdP.

### Criterios adicionales

- La primera fase define sesiones, revocación y passkeys sin asumir SAML/SCIM/IP.
- Cada feature plan-dependent tiene una decisión explícita de alcance y pruebas de revocación.
- SAML, SCIM, dominios e IP allowlists quedan fuera del MVP salvo requisito del despliegue.
