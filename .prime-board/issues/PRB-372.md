# Teams: implementar archivado reversible

Created by admin.

## Objetivo

Implementar el archivado reversible de un Team para poder retirar equipos históricos o inactivos del uso operativo sin borrar sus datos.

## Contexto

El Team histórico `AT` ya no tiene trabajo operativo, pero hoy prime-board no expone `team archive` ni `team delete`. Archivar sus Issues no elimina ni oculta el contenedor del Team.

## Alcance

- Agregar el estado de archivado del Team y las mutaciones GraphQL para archivar y restaurar.
- Excluir Teams archivados de listados, selectores y operaciones normales; permitir consulta explícita del historial archivado.
- Rechazar creación o mutaciones de Issues, estados, memberships, labels, cycles y demás recursos team-scoped cuando el Team está archivado.
- Preservar Issues, Workflow States, Activities, Repository Replica y relaciones existentes.
- Exponer la operación mediante CLI (`pb team archive` / `unarchive`) y MCP.
- Actualizar UI y documentación, con confirmación explícita antes de archivar.

## Criterios de aceptación

- Un Workspace Admin puede archivar y restaurar un Team; la autorización se valida en la API.
- El archivado es reversible y no borra datos ni cambia los identificadores existentes.
- Las consultas normales excluyen Teams archivados y una consulta explícita puede recuperarlos.
- Las mutaciones operativas contra un Team archivado devuelven un error de validación claro.
- CLI, MCP y UI reflejan el estado archivado y ofrecen restauración.
- Hay regresiones para autorización, filtrado, restauración y preservación de datos.
