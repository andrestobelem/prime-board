# Cycles: aplicar auto-add al crear un ciclo ACTIVE

Created by Micaela.

## Hallazgo reproducible

La revisión de `PRB-388` sobre `81fb5165bb57870ca5c9e5972b96f3f502a51f2f` detectó que `cycleAutoAddEnabled` no se aplica al crear directamente un ciclo ACTIVE y que la selección de estados no implementa las reglas documentadas para Completed/cooldown.

## Evidencia

Con `cycleAutoAddEnabled: true` y una Issue STARTED sin ciclo, `cycleCreate(state: ACTIVE, startsAt, endsAt)` deja `issue.cycle = null` en SQLite. `apps/server/src/domain/cycles.ts` llama auto-add al actualizar un ciclo en transición a ACTIVE (alrededor de las líneas 400–403) o en `advanceCycle` (808–810), pero `createCycle` solo repone cadence (263–269). PostgreSQL mantiene la misma asimetría (`postgres-cycles.ts`: transición/advance frente a creación). Además, `autoAddActiveIssues` solo filtra `unstarted`/`started`, nunca `completed` ni el contexto de cooldown.

## Comportamiento esperado

La creación directa de un ciclo ACTIVE debe aplicar la regla de auto-add a las Issues activas sin ciclo, o la API debe rechazar explícitamente la creación con estado ACTIVE y documentar que el avance es la única transición válida. Según `https://linear.app/docs/use-cycles`, Completed sin ciclo durante cooldown se atribuye al ciclo anterior y Started sin ciclo al siguiente ciclo.

## Criterios de aceptación

- [ ] SQLite y PostgreSQL tienen el mismo comportamiento al crear un ciclo ACTIVE.
- [ ] Con auto-add habilitado, las Issues Started/activas sin ciclo se asignan al ciclo correcto y generan la actividad esperada.
- [ ] Completed sin ciclo durante cooldown se asigna al ciclo anterior y Started sin ciclo al siguiente, según la fuente.
- [ ] Con auto-add deshabilitado, las Issues no se asignan.
- [ ] Existe regresión para la creación directa ACTIVE y para la ruta de avance.
- [ ] Si se rechaza ACTIVE en creación, la respuesta GraphQL, CLI y MCP usa un error de validación claro.
