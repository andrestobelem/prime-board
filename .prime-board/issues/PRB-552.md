# PostgreSQL: aislar API keys por grant y Membership efectiva

Created by admin.

## Hallazgo
PRB-516 corrige el aislamiento de API keys en el modelo SQLite multi-Workspace, pero la ruta PostgreSQL todavía lista, crea, rota o elimina API keys sin aplicar el grant `api_key_workspaces` y la Membership efectiva del Workspace.

## Evidencia
La revisión independiente de PRB-516 encontró brecha en `apps/server/src/domain/postgres-actors.ts:254-279`, `apps/server/src/domain/postgres-credentials.ts:155-188,200-237` y `apps/server/src/graphql/resolvers.ts:557-558,1461-1472`. PRB-513 corrige la autenticación PostgreSQL, pero no estos resolvers de API keys.

## Criterios de aceptación
- `Actor.apiKeys` PostgreSQL lista solo keys con grant en el Workspace efectivo.
- Crear una key exige Membership activa y grant del Workspace seleccionado.
- Rotar y eliminar exigen el grant/Membership efectivos y no cruzan Workspaces ni Team limits.
- Hay pruebas PostgreSQL reales con dos Workspaces, Membership activa/suspendida, grant ausente y Team limit cruzado.
- No se exponen secretos en logs, réplica ni respuestas no autorizadas.
