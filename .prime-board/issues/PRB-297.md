# CLI/MCP: exponer el archivado de issues

Created by admin.

## Hallazgo reproducible

El schema y la UI soportan `issueArchive`, y la guía documenta el ciclo `issueCreate → issueUpdate → commentCreate → issueArchive`, pero los clientes de agentes no:

- `pb issue archive PB-1` termina con código 2 y muestra el usage; `apps/cli/src/commands/issue.ts:25-38` no registra la acción ni llama a `issueArchive`.
- `apps/mcp/src/server.ts` no registra `archive_issue` ni un campo equivalente en `save_issue`.

Un agente que opera por CLI/MCP puede crear y editar issues, pero necesita GraphQL directo para completar el ciclo de vida y ocultar una issue.

## Comportamiento esperado

CLI y MCP deben exponer archivado con la misma autorización, resolución de referencias, errores y códigos de salida que GraphQL.

## Criterios de aceptación

- `pb issue archive <REF> [--json]` devuelve la issue archivada y códigos 0/1/2 consistentes.
- MCP ofrece `archive_issue` o una operación claramente equivalente.
- Se rechazan permisos y referencias inválidas sin mutaciones parciales.
- Actualizar ayuda, guía de agentes y tests de contrato.
