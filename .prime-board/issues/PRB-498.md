# Agentes: las sesiones del ciclo no muestran el nombre del Actor autenticado

Created by admin.

## Hallazgo

El experimento `PRB-493` lanzó cuatro sesiones concurrentes en worktrees y directorios de sesión aislados:

- `Scout` → `scratchpad/agent-runs/scout/sessions/`
- `Builder` → `scratchpad/agent-runs/builder/sessions/`
- `Micaela` → `scratchpad/agent-runs/micaela/sessions/`
- `Carorila` → `scratchpad/agent-runs/carorila/sessions/`

Cada sesión se autenticó con el Actor correcto y completó su Issue, pero los registros de sesión solo exponen un UUID y metadatos de cwd/branch. No contienen `sessionName`. El catálogo global de `prime-agent list --all --json` tampoco muestra estas sesiones cuando usan un `--session-dir` aislado.

## Comportamiento observado

La worktree y la carpeta local permiten inferir el Actor, pero el nombre visible de la sesión no coincide de forma verificable con `Scout`, `Builder`, `Micaela` o `Carorila`.

## Comportamiento esperado

Una sesión concurrente de un Agent debe mostrar un nombre estable que coincida con su Actor autenticado, o una etiqueta visible que mantenga una relación inequívoca con ese Actor. El nombre debe funcionar también con un directorio de sesión aislado.

## Criterios de aceptación

- [ ] Las sesiones concurrentes muestran `Scout`, `Builder`, `Micaela` y `Carorila`, o una convención equivalente y documentada.
- [ ] El nombre se conserva al persistir, listar y reabrir la sesión.
- [ ] La autenticación del Actor y el nombre visible no pueden quedar desalineados.
- [ ] El comportamiento funciona con `--session-dir` aislado.
- [ ] Hay una prueba o evidencia de cuatro sesiones simultáneas sin colisiones de nombres.
