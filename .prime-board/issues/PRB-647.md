# Seed: no ejecutar SQLite con backend PostgreSQL

Created by admin.

## Hallazgo

`scripts/demo-seed.ts` siempre llama `openDatabase(config.dbPath)` y usa dominios SQLite. Cuando `PRIME_BOARD_PERSISTENCE=postgres`, solo cambia la ruta usada para guardar credenciales; no usa `config.postgresUrl` ni `createPostgresPersistence`.

## Impacto

`bun run seed` puede sembrar una SQLite distinta mientras el servidor usa PostgreSQL. El operador puede interpretar el comando como un smoke test PG, aunque los datos y validaciones no se ejecutaron en PostgreSQL.

## Evidencia

- `apps/server/src/scripts/demo-seed.ts:15-23`.
- `apps/server/src/db/backend.ts` define el backend PostgreSQL, pero el script no lo usa.
- `docs/guia-agentes.md:124-132` documenta `bun run seed` sin limitarlo a SQLite.

## Aceptación

- [ ] Implementar seed mediante el backend configurado, incluido PostgreSQL; o
- [ ] Rechazar explícitamente `bun run seed` cuando el backend sea PostgreSQL y documentar la limitación.
- [ ] Probar que no se escribe SQLite accidentalmente durante un smoke test PG.
