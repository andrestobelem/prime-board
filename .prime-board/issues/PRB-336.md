# UI: ocultar o deshabilitar controles de Project y Cycle según ACL

Created by admin.

## Hallazgo reproducible

`ProjectView.tsx:228-248` siempre muestra Edit overview/Post update/Archive y `CycleView.tsx:89-99` siempre muestra Start/Complete. Ninguna vista consulta rol/membership. La API sí rechaza estos intentos: `project-resolvers.ts:173-196` llama `assertCanManageProject` y `resolvers.ts:702-705` llama `assertCanManageTeam`. Para member/outsider los controles aparecen activos y terminan en `UNAUTHORIZED` genérico.

## Comportamiento esperado

La UI debe reflejar la ACL efectiva: ocultar/deshabilitar acciones no permitidas o explicar el permiso requerido, manteniendo el bloqueo en API como defensa.

## Criterios de aceptación

- Owner/manager autorizado ve y puede usar las acciones correspondientes.
- Member sin permiso y outsider no reciben affordances activas para editar/archive/post/start/complete; si se muestran, explican el motivo.
- No se relaja la autorización del servidor ni se filtran detalles de recursos no visibles.
- Tests de UI y errores cubren roles y proyectos/cycles de teams distintos.

## Duplicados/relación

PRB-289 cubre controles de Team Settings y PRB-272/276 cubren ACL de API; ninguno cubre las affordances de Project/Cycle.
