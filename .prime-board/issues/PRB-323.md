# GraphQL: añadir cursor a issues anidadas de Projects y Milestones

Created by admin.

## Hallazgo reproducible

El SDL (`packages/schema/src/sdl.ts:402,459`) declara `Project.issues` y `Milestone.issues` como `issues(first: Int): IssueConnection!`, sin argumento `after`. Los resolvers (`apps/server/src/graphql/project-resolvers.ts:49-60,77-87`) llaman `listIssues` solo con `filter` y `first`. Con `scratchpad/audit-project-page.ts`, 51 issues y `first:50` devuelven 50 nodos y `hasNextPage:true`; intentar usar `after:endCursor` responde `Unknown argument "after"`.

## Comportamiento esperado

Toda conexión que anuncie `hasNextPage` debe ofrecer un cursor continuable y pasarlo al dominio, tanto para Projects como para Milestones.

## Criterios de aceptación

- `Project.issues` y `Milestone.issues` aceptan `after` (y conservan `first`), con validación de cursor consistente con `issues`.
- Se pueden recorrer más de 50 issues hasta `hasNextPage:false` sin repetir ni perder nodos.
- Los resolvers pasan el cursor al dominio y respetan filtros existentes.
- Hay tests GraphQL para ambas conexiones y para el caso sin siguiente página.

## Duplicados/relación

PRB-240 trata un límite de UI de Projects/Planning; PRB-274 trata paridad de clientes. Ninguno cubre la forma GraphQL sin cursor.
