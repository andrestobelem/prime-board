# UI: hacer funcional el onboarding link de API keys

Created by admin.

## Hallazgo reproducible

`apps/web/src/views/MembersView.tsx:121-123` genera `${origin}/?key=${key}`, pero `apps/web/src/api.ts:6-8` solo lee `localStorage.pb.apiKey`; no existe lector del parámetro `key` en App/Settings. En un navegador limpio, abrir el enlace copiado deja la app sin credenciales y muestra el flujo de Settings/`UNAUTHORIZED`; el parámetro se ignora.

## Comportamiento esperado

Abrir un onboarding link debe consumir la key de forma segura (prellenarla/guardarla según el flujo diseñado) o mostrar una instrucción accionable para completar la autenticación.

## Criterios de aceptación

- Un navegador/perfil sin credenciales abre el enlace y queda autenticado o en un flujo explícito para guardar la key.
- La key no aparece en URLs internas/logs más tiempo del necesario y no pisa una credencial existente sin confirmación.
- Una key inválida/expirada muestra error accionable.
- Hay regresiones para perfil limpio, key válida e inválida.

## Duplicados/relación

PRB-235 cubre ownership de actores/API keys y PRB-271 el menú de cuenta; ninguno cubre el enlace de onboarding.
