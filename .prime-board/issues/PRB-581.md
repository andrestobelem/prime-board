# Webhooks PostgreSQL: conservar team key en issue.updated

Created by admin.

## Hallazgo de revisión independiente de PRB-389

En la ruta PostgreSQL de `issue.updated`, `apps/server/src/graphql/resolvers.ts:367-370` carga `IssueRow` con `SELECT * FROM issues WHERE id = $1`, sin `teams.key AS team_key`. Después `issueEventData(issue)` usa `IssueRow.identifierOf()`, que construye `${row.team_key}-${row.number}`.

En merge/delete de labels PostgreSQL, el webhook puede emitir `identifier: "undefined-1"` y los consumidores pierden el identificador válido. SQLite sí usa un lookup con el join correcto.

## Comportamiento esperado

Todo payload de webhook PostgreSQL debe incluir el identificador estable `<TEAM_KEY>-<number>`.

## Criterios de aceptación

- [ ] La carga PostgreSQL de Issues para eventos incluye `teams.key AS team_key`, o usa un helper equivalente.
- [ ] `issueEventData` nunca produce `undefined-<number>`.
- [ ] Existe regresión para merge/delete de labels o para el emisor común.
- [ ] Focales, typecheck, Prettier y diff-check pasan.
