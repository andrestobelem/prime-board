# Tests: aislar fixtures Git del hook pre-commit

Created by admin.

## Hallazgo reproducible

Al ejecutar el hook real de pre-commit desde un worktree limpio para `PRB-566`, la suite global terminó con 22 fallos y dejó el worktree mutado:

- La rama `admin/prb-566-replica-enobufs` avanzó desde `2ae06b0` a varios commits `fixture` (`908b906`, `46dd43e`, `efcf632`, `4063062`).
- El índice terminó con solo ocho archivos de sentinel/preflight.
- El resto del checkout apareció como archivos no rastreados o borrados.
- Fue necesario recuperar la rama con `git reset --mixed 2ae06b0` y descartar los efectos del fixture.

El hook no debe modificar el `HEAD`, el índice ni los archivos del worktree que lo invoca. `PRB-543` cubre el preflight y el aislamiento de worktrees, pero este caso específico deja una mutación destructiva durante el hook.

## Comportamiento esperado

La suite y sus fixtures ejecutan cada operación Git en repositorios temporales aislados y conservan intactos el branch, el índice y los archivos del worktree llamador, incluso cuando una prueba falla.

## Criterios de aceptación

- [ ] El hook ejecutado en un worktree limpio conserva exactamente `HEAD`, el índice y el estado de archivos.
- [ ] Los fixtures Git nunca inicializan ni reemplazan el repositorio llamador.
- [ ] Una suite fallida deja un diagnóstico, pero no cambia la rama ni elimina archivos rastreados.
- [ ] Hay una regresión que detecta el cambio de `HEAD` y del índice durante el hook.
- [ ] Las suites focales, el preflight, typecheck, Prettier y `git diff --check` pasan.

## Evidencia

- Comando: `git commit` con el hook real desde el worktree de `PRB-566`.
- Resultado: hook fallido; `HEAD` quedó en un commit `fixture` con un árbol incompleto.
- Recuperación: `git reset --mixed 2ae06b0` restauró el índice sin descartar el cambio de `PRB-566`.

## Fuera de alcance

No cambiar la lógica de Repository Replica ni el contrato del Event Log.
