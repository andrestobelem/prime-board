# Git: las worktrees dejan el checkout principal como bare

Created by admin.

## Hallazgo

Durante el experimento PRB-493, después de crear cuatro worktrees aisladas y ejecutar agentes, el checkout principal quedó con `core.bare=true` en `.git/config`.

## Evidencia

En `/Users/andrestobelem/ws/at/prime-board`:

```text
$ git status --short --branch
fatal: this operation must be run in a work tree

$ git diff
fatal: this operation must be run in a work tree
```

La configuración local contiene `core.bare=true`. Antes de preparar las worktrees, `git status` funcionaba y reportaba `main...origin/main`.

## Comportamiento esperado

Crear o usar worktrees no debe cambiar el checkout principal a un repositorio bare. `git status`, `git diff` y `git rev-parse --show-toplevel` deben seguir funcionando en la raíz.

## Criterios de aceptación

- [ ] La configuración del checkout principal conserva `core.bare=false` o no define el valor.
- [ ] Crear, usar y eliminar worktrees no cambia el estado bare del checkout principal.
- [ ] Hay una prueba o diagnóstico reproducible que detecta este cambio.
- [ ] Se conserva la evidencia del proceso que produjo el cambio, sin editar `.prime-board` a mano.
