# Documents: scopear targetTeamIds y ACL por Workspace

Created by admin.

## Hallazgo de auditoría de PRB-517

`apps/server/src/graphql/document-resolvers.ts:292-318` (`targetTeamIds`) consulta `project_teams`, `initiative_teams` y `initiative_projects` por IDs sin `workspace_id`. `documentVisible` usa esos Teams para ACL/API-key y el nested Initiative los expone.

Con dos Workspaces y referencias homónimas, un Document puede mezclar Teams de otro Workspace y autorizar o exponer datos ajenos. El commit `d8f31b9` no corrige este helper ni añade una matriz real de dos Workspaces.

## Comportamiento esperado

Los joins y referencias de Document deben filtrarse por el Workspace efectivo. Un ID de otro Workspace debe devolver `NOT_FOUND` o un resultado no visible, sin autorizar ni exponer el Document.

## Criterios de aceptación

- [ ] `targetTeamIds` recibe contexto Workspace obligatorio.
- [ ] Todos los joins `project_teams`, `initiative_teams` e `initiative_projects` aplican el scope efectivo.
- [ ] ACL/API-key y nested Initiative no cruzan Workspaces.
- [ ] Regresión real con dos Workspaces y referencias homónimas.
- [ ] Focales, typecheck, Prettier y diff-check pasan.
