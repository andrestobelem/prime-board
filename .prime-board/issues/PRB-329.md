# CLI/MCP: ofrecer una forma explícita de limpiar la descripción de un issue

Created by admin.

## Hallazgo reproducible

La API admite `description: String` nullable en `IssueUpdateInput`. El CLI solo agrega `description` cuando `values.description` es truthy, por lo que `--description ""` no puede limpiar el valor; MCP declara un string opcional y rechaza `null`. Esto impide un round-trip de actualización soportado por GraphQL desde clientes de agentes.

## Comportamiento esperado

CLI y MCP deben ofrecer una semántica explícita, segura y documentada para distinguir no modificar de limpiar la descripción (por ejemplo `--description none`/flag dedicado y `null` en el schema MCP).

## Criterios de aceptación

- Crear una descripción, limpiarla y volver a leerla funciona desde CLI y MCP.
- Omitir el argumento continúa significando no modificar.
- La forma de clear no confunde una cadena vacía válida con ausencia y tiene tests de round-trip/error.
- La documentación explica la semántica y los errores de tipo.
