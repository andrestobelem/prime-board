# Migración: el rebuild de issues deja el índice FTS externo desincronizado

Created by admin.

## Hallazgo

La migración `0025_workspace_constraints.sql` de `scout/prb-472`:

1. Elimina los triggers de `issues_fts`.
2. Copia `issues` a `_prb25_issues`.
3. Elimina y renombra la tabla `issues`.
4. Crea otra vez los triggers.

No limpia ni reconstruye la tabla virtual FTS5 `issues_fts`, que usa `content='issues'` y `content_rowid='rowid'`.

## Comportamiento esperado

Una base legacy que migra debe conservar la búsqueda full-text de todos los Issues, sin depender de que SQLite asigne los mismos rowids durante el rebuild.

## Criterios de aceptación

- [ ] La migración reconstruye o valida `issues_fts` después de reemplazar `issues`.
- [ ] Un Issue legacy sigue apareciendo en una búsqueda FTS después de la migración.
- [ ] La prueba cubre rowids no contiguos o un orden de copia diferente.
- [ ] Las escrituras, actualizaciones y borrados posteriores mantienen el índice sincronizado.
