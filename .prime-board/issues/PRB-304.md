# Export parcial: cerrar el alcance de metadatos antes de permitir rebuild

Created by admin.

## Hallazgo reproducible

Un export parcial de un team incluye metadatos de otros teams:

1. Crear teams `PB` y `OT`, un proyecto/iniciativa/review/cycle de `OT` y datos de `PB`.
2. Ejecutar `exportBoard`/`bun run export --team PB`.
3. El export declara alcance `team:PB`, pero `meta/projects.json`, `meta/initiatives.json` y otros metadatos todavía contienen recursos de `OT`; `meta/teams.json` solo contiene `PB`.
4. `rebuild --allow-partial` sobre una DB limpia falla con `Initiative "OT init" references unknown team OT` y la transacción deja el destino sin teams.

Evidencia: el exportador filtra teams/issues/saved views pero no cierra el alcance para proyectos, iniciativas, updates, reviews, cycles e inbox receipts. PRB-247 cubre una variante de saved views, no el resto del índice.

## Comportamiento esperado

Un export parcial debe ser internamente consistente y reconstruible dentro de su alcance, o fallar antes de modificar la DB con un diagnóstico que enumere todas las referencias fuera de alcance.

## Criterios de aceptación

- Cada archivo de `meta/` respeta el alcance declarado o se omite/recorta con reglas documentadas.
- `rebuild --allow-partial` valida el grafo completo antes de borrar/escribir.
- Un rechazo deja intacta la DB destino.
- Agregar round-trip para teams con proyectos, iniciativas, updates, reviews, cycles, inbox y relaciones.
