# Web: aplicar access policy y status al selector de assignee

Created by admin.

## Objetivo
Evitar que Team List ofrezca actores que el Team no permite asignar.

## Evidencia
- `apps/web/src/views/TeamView.tsx` consulta actores del Workspace sin `status`, `accessPolicy` ni roster.
- `BoardView.tsx` ya filtra actores activos y respeta `TEAM_MEMBERS`.
- Las dos superficies ofrecen opciones distintas para la misma mutación.

## Criterios de aceptación
- [ ] Team List usa la misma regla de actores que Board.
- [ ] Actors suspendidos no aparecen como opción.
- [ ] `TEAM_MEMBERS` limita la lista al roster del Team.
- [ ] `WORKSPACE_MEMBERS` usa solo actores activos accesibles.
- [ ] Hay pruebas para owner, member, outsider y actor suspendido.
