# Cycles: validar fechas DateTime antes de persistir

Created by admin.

## Hallazgo reproducible

`cycleCreate` acepta fechas inválidas porque el scalar `DateTime` deja pasar cualquier string y `createCycle` solo compara `startsAt > endsAt` lexicográficamente. Una mutación con `startsAt: "not-a-date"` y `endsAt: "zzz"` responde `success: true` y persiste ambos valores.

## Evidencia

- `apps/server/src/domain/cycles.ts`: valida únicamente `if (input.startsAt > input.endsAt)`.
- `packages/schema/src/sdl.ts`: `DateTime` no valida formato en el scalar.
- Reproducción aislada con `createTestApp`: `cycleCreate` devuelve `{"startsAt":"not-a-date","endsAt":"zzz"}`.
- Los tests cubren orden de fechas, pero no strings no parseables.

## Comportamiento esperado

Las fechas de ciclos deben ser DateTime ISO-8601 válidas y `startsAt` no puede ser posterior a `endsAt`; una entrada inválida debe fallar antes de persistir.

## Criterios de aceptación

- [ ] `cycleCreate` y `cycleUpdate` rechazan fechas no parseables con `VALIDATION_FAILED`.
- [ ] Se acepta el formato DateTime soportado por la API y se conserva su valor normalizado o válido.
- [ ] Una fecha inicial posterior al cierre continúa siendo rechazada.
- [ ] Hay regresiones que verifican que no se persisten ciclos inválidos.
