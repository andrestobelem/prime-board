# GraphQL: mantener subscriptions válidas en el fallback legacy

Created by Builder.

## Hallazgo de revisión de PRB-580

El fallback legacy compartido transforma una `subscription` cuya selección queda vacía en `subscription S { __typename }`. GraphQL permite `__typename` en otros roots, pero lo prohíbe en el root de `Subscription`. El documento se puede parsear, pero falla validación y la request legacy no es válida.

**Reproducción:**

```graphql
subscription S($workspaceId: ID!) { workspaceId }
```

El transformador produce `subscription S { __typename }`.

## Comportamiento esperado

El fallback debe conservar un documento GraphQL válido para cualquier operación soportada, incluida `subscription`, o rechazar de forma explícita una operación que no tenga una selección legacy válida. No debe enviar un campo introspection prohibido al root de `Subscription`.

## Criterios de aceptación

- [ ] Una subscription legacy con selección `workspaceId` no genera un root inválido.
- [ ] Una subscription con una selección objeto que queda vacía conserva una validación GraphQL válida o devuelve un error explícito antes de enviar.
- [ ] Queries y mutations conservan el fallback actual.
- [ ] Existe regresión de validación para `subscription`.
- [ ] El cambio queda relacionado con PRB-580 sin modificar la semántica moderna.
