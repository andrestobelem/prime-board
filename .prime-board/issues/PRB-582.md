# MCP: exponer rescope de Labels con Workspace seguro

Created by admin.

## Hallazgo de revisión independiente de PRB-389

MCP no expone el rescope de Label. `save_issue_label` declara `team` como “Team key or ID (create only)” (`apps/mcp/src/server.ts:681`). En la rama de update solo envía `name`, `color`, `description` y `groupId` (`:687-690`); no envía `teamId`.

GraphQL y CLI sí soportan `labelUpdate.teamId`, pero un agente que opera por MCP no puede mover una Label entre Workspace y Team, ni entre Teams.

## Comportamiento esperado

La superficie MCP debe exponer el rescope permitido por el contrato de Labels, con validación de Workspace, permisos y terminalidad de Labels mergeadas.

## Criterios de aceptación

- [ ] `save_issue_label` acepta el cambio de scope cuando el input lo solicita.
- [ ] MCP envía `teamId` en la mutación de update y soporta `null` para scope Workspace.
- [ ] Cross-Workspace y Labels mergeadas se rechazan de forma estable.
- [ ] Existe regresión MCP para rescope válido e inválido.
- [ ] Focales, typecheck, Prettier y diff-check pasan.
