# Issues: agregar fechas operativas y due date

Created by admin.

## Objetivo
Agregar al modelo de Issue las fechas necesarias para planificación y para reconstruir su ciclo de trabajo.

## Evidencia
- `packages/schema/src/sdl.ts` no expone `dueDate`, `startedAt`, `completedAt` ni `canceledAt` en `Issue` ni en sus inputs.
- `apps/server/src/db/migrations/0001_init.sql` no tiene columnas para esas fechas.
- `docs/audits/linear-paridad-graphql.md` clasifica estos campos como ausentes.
- `docs/relevamiento-linear.md` considera los timestamps del ciclo parte del núcleo y `due date` una capacidad deseable.

## Comportamiento esperado
La API conserva fechas de planificación y registra de forma determinista las transiciones de estado.

## Criterios de aceptación
- [ ] `Issue` expone `dueDate`, `startedAt`, `completedAt` y `canceledAt` con semántica documentada.
- [ ] `IssueCreateInput` y `IssueUpdateInput` permiten actualizar `dueDate` con validación de fecha.
- [ ] Las transiciones a `started`, `completed` y `canceled` fijan o limpian sus timestamps según la regla definida.
- [ ] Los filtros y el orden documentan los campos soportados.
- [ ] GraphQL, CLI, MCP y export/rebuild conservan los valores.
- [ ] Hay migración compatible, pruebas de transición y prueba de round-trip.
