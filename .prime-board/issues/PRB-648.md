# Export PostgreSQL: preservar memberships y grants de Workspace

Created by admin.

## Hallazgo

`exportPostgresBoard` no copia `workspace_memberships`, `api_key_workspaces` ni `actor_invitations`. El snapshot conserva algunos datos globales de Actors y metadata de API keys, pero no todas las filas que PostgreSQL usa para autenticación y ACL.

El rebuild SQLite recrea memberships y el grant default mediante triggers en el caso singleton, pero no puede conservar memberships por Workspace, grants adicionales de una key o invitaciones pendientes.

## Impacto

Un roundtrip PostgreSQL → repo → rebuild puede cambiar permisos y acceso sin conflicto: puede perder membresías con estado/rol distinto, grants multi-Workspace e invitaciones. El resultado de un smoke test con Actors/keys puede no representar la ACL real de PostgreSQL.

## Evidencia

- `apps/server/src/export/postgres-export.ts:7-40` excluye las tres tablas.
- `apps/server/src/export/exporter.ts:559-600` exporta Actors y metadata de keys, no memberships/grants/invitations.
- `apps/server/src/export/importer.ts:296-329` lee scopes/Team limits locales, pero no snapshots de esas tablas.
- Auth PostgreSQL consulta `workspace_memberships` y `api_key_workspaces` directamente.
- `docs/research/sqlite-postgresql-podman.md` enumera estas entidades como parte de la migración/auth.

## Aceptación

- [ ] Definir y documentar si estas filas forman parte del contrato de export/rebuild.
- [ ] Preservar o rechazar explícitamente roundtrips que no puedan conservarlas.
- [ ] Probar memberships, grants multi-Workspace e invitaciones con PostgreSQL real.
- [ ] No presentar un smoke test SQLite como validación de ACL PostgreSQL.
