# CLI/MCP: completar superficies administrativas para actores, memberships, workflow y labels

Created by admin.

## Hallazgo reproducible

El schema expone mutaciones administrativas para `teamCreate/Update`, `teamMembershipCreate/Delete`, `actorCreate/Update`, `apiKeyCreate/Delete`, `workflowStateCreate/Update/Delete` y `labelCreate/Update/Delete`, pero el CLI solo ofrece `team list` y el MCP no registra esas mutaciones. La guía todavía instruye usar `curl` para crear actores/API keys (`docs/guia-agentes.md:49-71`).

Un agente que opera únicamente por CLI/MCP no puede darse de alta, rotar su API key, invitar miembros ni adaptar el workflow/labels; debe abandonar la superficie declarada y usar GraphQL directo.

## Comportamiento esperado

La matriz pública debe exponer estas operaciones administrativas donde corresponda, con referencias amigables, permisos, códigos de error y secretos de API key consistentes. Si alguna operación queda deliberadamente fuera, debe documentarse como excepción en vez de afirmar paridad total.

## Criterios de aceptación

- Decidir y documentar el alcance CLI/MCP por operación.
- Exponer al menos el flujo de alta/rotación de actores y API keys y la administración de memberships/team config soportada.
- No imprimir hashes ni claves existentes; mostrar una nueva key una sola vez.
- Cubrir admin/owner/member/outsider, resolución de referencias, `--json` y errores MCP.
