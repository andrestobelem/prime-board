# Configurar identidad del Workspace y Team en el bootstrap CLI/env

Created by admin.

## Contexto

El bootstrap automático crea el Workspace y el Team inicial con valores fijos (`workspace` / `prime-board` y `Prime Board` / `PB`). Esto impide decidir la identidad estable de una instancia al lanzarla.

## Alcance

Agregar un contrato único de configuración para el bootstrap de SQLite y PostgreSQL:

- `workspaceName` / `PRIME_BOARD_WORKSPACE_NAME`
- `workspaceUrlKey` / `PRIME_BOARD_WORKSPACE_URL_KEY`
- `teamName` / `PRIME_BOARD_TEAM_NAME`
- `teamKey` / `PRIME_BOARD_TEAM_KEY`

El launcher debe exponer flags equivalentes y pasarlos al servidor. Las variables de entorno deben servir para ejecuciones automatizadas sin interacción. Los valores omitidos conservan los defaults actuales para compatibilidad.

## Reglas

- Validar los cuatro valores antes de insertar datos.
- Mantener separada la identidad estable (`urlKey`/`key`) del nombre visible.
- No modificar un Workspace o Team existente durante un reinicio.
- Aplicar la misma configuración al bootstrap SQLite y PostgreSQL.
- Documentar nombres de flags, variables, defaults y restricciones.

## Criterios de aceptación

- Un arranque sobre una base vacía crea los cuatro valores solicitados.
- Flags y variables producen el mismo resultado.
- Los defaults actuales siguen funcionando cuando no se especifica configuración.
- Un valor inválido produce un error claro antes de crear datos parciales.
- Un arranque sobre una base existente conserva su identidad.
- Hay pruebas focalizadas para parsing/validación y para ambos backends, o una verificación equivalente si el harness de PostgreSQL no es práctico.
