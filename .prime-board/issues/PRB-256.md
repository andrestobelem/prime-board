# AUDIT: spike de auditoría integral post-PRB-255

Created by admin.

## Clasificación

Este issue es un **spike de auditoría** (investigación y registro), no un ticket de corrección. En prime-board no existe un campo `type` separado para “spike”; la clasificación queda explícita en el título y esta sección.

El estado de workflow `In Progress` indica que la auditoría está activa. Los hallazgos nuevos se crearán como issues separados en `Needs Triage`; después del triage pasarán a `Todo`, `Ready for Agent` o `Ready for Human` según corresponda.

## Objetivo

Revisar el estado posterior a PRB-255 de prime-board, encontrar errores, contratos rotos, regresiones, riesgos operativos y divergencias funcionales, y registrar cada hallazgo accionable como ticket propio.

## Reglas

- No corregir código dentro de este spike.
- Cada hallazgo reproducible recibe su propio issue antes de corregirse.
- Cada issue nuevo incluye evidencia, comportamiento esperado, impacto y criterios de aceptación.
- Las correcciones se implementan después del cierre de la auditoría, una por ticket y con commit separado.

## Alcance

- API GraphQL, dominio, permisos y autenticación.
- SQLite, migraciones, export/rebuild, réplica `.prime-board/` y round-trips.
- Webhooks, CLI, MCP, sincronización y operación local.
- Frontend funcional, responsive y accesibilidad básica.
- Tests, typecheck, build, documentación y configuración.

La comparación estética con Linear solo se repite si aparece una regresión accionable; no se mezcla con la clasificación de los hallazgos.

## Criterios de salida

- [ ] Todos los sub-issues de auditoría están completados.
- [ ] Cada hallazgo accionable tiene un issue propio en estado triage o posterior.
- [ ] No quedan resultados ambiguos sin decisión documentada.
- [ ] Este spike contiene el resumen de comandos, superficies revisadas y excepciones.
