# CLI: completar campos de Projects e Initiative Updates

Created by admin.

## Hallazgo

La revisión de PRB-391 encontró que el cliente CLI no expone todo el contrato de planning. `apps/cli/src/commands/project.ts` incluye `members` y `startDate`, pero omite `teams` y `dependencies`. `apps/cli/src/commands/initiative.ts` omite `updates` y no ofrece comandos para Initiative Updates.

## Comportamiento esperado

El CLI debe consumir el contrato GraphQL vigente sin perder relaciones de planning ni datos de updates. Debe conservar compatibilidad legacy, aplicar WorkspaceContext/ACL y no inventar campos que la API no soporte.

## Criterios de aceptación

- [ ] `project list/get/save` exponen `teams` y `dependencies` cuando la API los devuelve.
- [ ] `initiative list/get/save` exponen `updates` y sus campos estables.
- [ ] Existen operaciones CLI para crear/editar/borrar Initiative Updates si el contrato público las soporta; si no, se documenta el límite.
- [ ] Selector de Workspace y errores conservan el scope efectivo.
- [ ] Tests cubren respuestas legacy, relaciones, updates, errores y compatibilidad.
- [ ] Typecheck, Prettier y diff-check pasan; no se registran secretos.
