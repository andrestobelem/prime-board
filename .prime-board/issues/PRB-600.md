# Documentación: alinear mapeo histórico de Duplicate con PRB-540

Created by admin.

## Hallazgo

La documentación vigente contradice la decisión de PRB-540 sobre `Duplicate`.

## Evidencia

- `docs/specs/migracion-linear.md` alrededor de la línea 80 indica crear un estado con el mismo nombre y `State Type canceled`.
- `docs/specs/cutover-linear.md` alrededor de la línea 17 conserva un warning `Duplicate` como `canceled` sin explicar el contrato vigente.
- PRB-540 está `Done` y decidió que `Duplicate` no es un estado: se usa la relación `duplicate-of` y la Issue se cancela con `Canceled`.

Los snapshots históricos de `docs/migrations/*.json` pueden conservarse como evidencia histórica, pero no deben presentarse como contrato actual.

## Comportamiento esperado

Las especificaciones operativas y de migración describen el modelo vigente: no se crea ni se restaura un estado `Duplicate`; las referencias históricas se mapean a `Canceled` y la duplicación se expresa con `duplicate-of`.

## Criterios de aceptación

- `docs/specs/migracion-linear.md` coincide con PRB-540.
- `docs/specs/cutover-linear.md` distingue contrato vigente de evidencia histórica.
- La documentación no instruye crear un estado `Duplicate`.
- Hay una referencia explícita a PRB-540 y a la relación `duplicate-of`.
