# Frontend: ignorar respuestas obsoletas al cambiar filtros o navegar

Created by admin.

## Hallazgo reproducible

`useQuery` puede dejar resultados de una consulta anterior después de que cambian variables:

1. Abrir una lista y usar DevTools Slow 3G o un proxy con latencia variable.
2. Cambiar rápidamente la búsqueda/filtro (o navegar a otro team/issue) dos veces.
3. La request vieja puede completar después de la nueva; `apps/web/src/api.ts:63-73` ejecuta `setData(result)` en cada `.then` sin abortar ni comprobar un request id.
4. La lista termina mostrando resultados del filtro/ruta anterior aunque el input/URL ya representa el nuevo.

## Comportamiento esperado

Solo la respuesta de la consulta vigente debe actualizar data/loading/error. Las requests obsoletas deben cancelarse o ignorarse, especialmente antes de permitir acciones destructivas sobre una lista visible.

## Criterios de aceptación

- Cambios rápidos de variables y navegación no muestran resultados stale.
- AbortController o request-generation guard evita que una respuesta vieja sobrescriba la actual.
- Loading/error corresponden a la consulta vigente y no se produce parpadeo de datos incorrectos.
- Agregar test con resoluciones fuera de orden y conservar el comportamiento de cache/refresh actual.
