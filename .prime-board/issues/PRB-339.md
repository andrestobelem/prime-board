# Export: conservar snapshot al exportar un issue con comentario

Created by admin.

## Hallazgo reproducible

Durante la revisión de la sincronización repo, `exportBoard` y `exportIssue` omiten el snapshot Markdown cuando la última actividad del issue es `commented`. En un directorio `.prime-board` nuevo, solo se escribe el log JSONL; `rebuildFromRepo` descubre issues leyendo `issues/*.md`, por lo que el issue y sus comentarios se pierden al reconstruir.

## Comportamiento esperado

Un export sobre un repositorio vacío debe escribir siempre el snapshot mínimo del issue, aunque la última actividad sea un comentario. El optimizado que evita reescribir un snapshot existente no debe ocultar snapshots ausentes.

## Criterios de aceptación

- Exportar un issue recién comentado a un root vacío crea su Markdown y log.
- Rebuild conserva el issue y el comentario.
- Exportar sobre un snapshot existente sigue evitando reescrituras innecesarias.
