# CLI/MCP: completar filtros y campos de ciclo/reordenamiento de issues

Created by admin.

## Hallazgo reproducible

GraphQL permite `IssueUpdateInput.cycleId` y `sortOrder`, y `IssueFilter` permite `creator`, `milestone`, `cycle`, `parent`, `labels` y comparadores. Los clientes de agentes no exponen esas capacidades:

- `pb issue update` no acepta `--cycle` ni `--sort-order`; `pb issue list` no filtra por creator/milestone/cycle/parent/labels.
- MCP `save_issue` no acepta cycle/sortOrder y `list_issues` solo expone team/state/assignee/project/query/unblocked.

Un agente no puede asignar una issue a un ciclo, conservar el orden del board ni construir una cola equivalente a un filtro guardado sin GraphQL directo.

Evidencia: `packages/schema/src/sdl.ts:IssueFilter/IssueUpdateInput`; `apps/cli/src/commands/issue.ts` y `apps/mcp/src/server.ts:107-250` no modelan esos inputs. PRB-239/240 cubren dominio/UX, no la paridad CLI/MCP.

## Comportamiento esperado

CLI y MCP deben ofrecer los campos y filtros soportados, o documentar una matriz explícita de excepciones para que un agente no asuma capacidades inexistentes.

## Criterios de aceptación

- Agregar update de cycle/sortOrder y filtros de creator/milestone/cycle/parent/labels con resolución de nombres/IDs.
- Mantener `--json`, límites, errores y autorización consistentes.
- Cubrir filtros anidados/comparadores y round-trip de sortOrder en tests de contrato.
