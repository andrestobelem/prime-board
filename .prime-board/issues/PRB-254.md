# Webhooks: validar eventos desconocidos al crear la suscripción

Created by admin.

## Hallazgo reproducible

`WebhookCreateInput.events` acepta cualquier string y `createWebhook` lo persiste sin validarlo. El dispatcher solo emite el conjunto cerrado `issue.created`, `issue.updated`, `issue.archived`, `comment.created`, `project.created` y `project.updated`. Por lo tanto, una suscripción como `events: ["issue.typo"]` se crea con éxito pero nunca recibe entregas y no informa el error al cliente.

## Evidencia

- `packages/schema/src/sdl.ts`: `events: [String!]` sin enum.
- `apps/server/src/domain/webhooks.ts`: persiste `input.events` sin validar.
- `apps/server/src/webhooks/dispatcher.ts`: `WebhookEventName` es un conjunto cerrado y filtra por coincidencia exacta.
- `apps/server/src/graphql/webhooks.test.ts` cubre URL, firma y filtrado, pero no eventos desconocidos.

## Comportamiento esperado

La creación debe rechazar eventos desconocidos con `VALIDATION_FAILED` (o exponer un enum compartido), aceptar `*` y todos los eventos soportados, y no dejar suscripciones que aparenten estar activas pero no puedan dispararse.

## Criterios de aceptación

- [ ] El schema y la validación comparten la lista de eventos soportados.
- [ ] Un evento desconocido falla antes de persistir el webhook y devuelve un error accionable.
- [ ] `*` y cada evento soportado continúan funcionando.
- [ ] Hay regresiones que verifican que no se crea una fila ante una entrada inválida.
