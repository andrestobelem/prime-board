# Comments: actualizar updatedAt del issue para sincronización incremental

Created by admin.

## Hallazgo reproducible

`commentCreate` registra el comentario y Activity, pero no actualiza `issues.updated_at`:

1. Crear `PB-1` y guardar su `updatedAt`.
2. Esperar unos milisegundos y ejecutar `commentCreate` sobre el issue.
3. La respuesta confirma el comentario y aparece Activity `commented`, pero `issue.updatedAt` conserva exactamente el valor anterior.

Así, clientes que consultan `issues(orderBy: UPDATED_DESC)` o recorren cursores para polling incremental no detectan comentarios nuevos.

## Comportamiento esperado

Toda mutación que cambia la actividad observable de un issue debe actualizar `updatedAt`, o el contrato de sincronización debe declarar y cubrir explícitamente una fuente alternativa.

## Criterios de aceptación

- `commentCreate` actualiza `issues.updated_at` de forma monotónica.
- La issue aparece en consultas `UPDATED_DESC` y páginas posteriores de sincronización.
- Mantener Activity, webhooks y comentarios consistentes sin actualizar por lecturas.
- Agregar regresión para comentario creado después de la issue y documentar la semántica para polling.
