# Webhooks: rechazar eventos con recurso de otro Workspace

Created by Scout.

## Hallazgo reproducible

`WebhookDispatcher.emitForWorkspace()` acepta un Workspace explícito, pero no valida que los IDs de `data` pertenezcan a ese Workspace. Si un evento de una Issue del Workspace A se etiqueta con `_workspaceId` de B, el filtro de Teams devuelve vacío y los Webhooks de B reciben el payload.

## Comportamiento esperado

El dispatcher debe validar la coherencia entre el Workspace efectivo y el recurso del evento. Una combinación incoherente debe fallar cerrado y no debe entregar el evento a ningún Webhook.

## Criterios de aceptación

- [ ] Un evento con `issueId`/`teamId` de A y Workspace explícito B no se entrega.
- [ ] La validación cubre Issue, Team y Project sin romper `team.deleted` después de borrar el Team.
- [ ] El payload público conserva el Workspace solo cuando el recurso es coherente.
- [ ] Existe una regresión con dos Workspaces y no se registran secretos.
