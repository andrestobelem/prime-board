# Propagar Workspace Context a las operaciones de Actor

Created by admin.

## Hallazgo
`actorInvite` no pasa Workspace Context al dominio (`apps/server/src/graphql/resolvers.ts:1308-1323`) y `createActorInvitation` inserta sin `workspace_id` (`apps/server/src/domain/actors.ts:433-479`). En una base SQLite con más de un Workspace la escritura falla con `Workspace context is required for actor_invitations`. `suspend`, `revoke` y `leave` siguen mutando estado global del Actor (`apps/server/src/domain/actors.ts:561-604`).

## Criterios de aceptación
- Invitaciones, suspensión, revocación y salida reciben y validan el Workspace efectivo.
- Las invitaciones se guardan en el Workspace correcto.
- Las mutaciones no afectan Memberships, actores o keys de otro Workspace.
- Hay pruebas multi-Workspace para autorización y aislamiento.
