# Implementar event log canónico y proyecciones repo–PostgreSQL

Created by admin.

## What to build
Convertir export/import y repo sync en el event log canónico del Repository Source y en un projector idempotente hacia PostgreSQL.

## Acceptance criteria
- [ ] Cada mutación durable genera un evento versionado, autosuficiente e idempotente, y sigue `append event → commit Git → project PostgreSQL`.
- [ ] El projector mantiene checkpoint, permite replay completo y hace visible el lag o el fallo sin perder eventos.
- [ ] Issue Markdown y metadata se regeneran desde el Log; no se mergean snapshots manualmente.
- [ ] Un importador Markdown explícito solo emite eventos y nunca escribe directamente en PostgreSQL.
- [ ] Secrets de API keys/webhooks y Favorites/Inbox receipts quedan fuera del estado compartido canónico.
- [ ] Un merge `union` de Logs produce proyecciones deterministas y un round-trip validado.
