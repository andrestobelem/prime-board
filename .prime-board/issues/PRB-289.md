# Team Settings: ocultar controles de configuración para no owners

Created by admin.

## Hallazgo reproducible

Run QA aislado: `20260817T221922Z-e2e`, commit `95b3e6b1051529dc7065ff59a1fb25788a6f267f`, target `http://localhost:3345`, team `PB`.

La ruta SPA `/#/team-settings/PB` responde `200` para owner, manager, contributor, agent y viewer. En `apps/web/src/App.tsx`, el enlace y la vista de Team Settings no se condicionan por rol. `apps/web/src/views/TeamSettingsView.tsx` consulta el team y renderiza para cualquier viewer autenticado controles activos para:

- crear/editar/borrar workflow states;
- cambiar el default state;
- crear/editar/borrar labels, incluido el selector workspace/team.

La vista no consulta `viewer.workspaceRole` ni membership/role. Al usarse con manager, contributor, agent o viewer, los controles se muestran aunque GraphQL rechaza las mutaciones con `UNAUTHORIZED` (`Team owner permission is required`). El resultado es un control engañoso: el usuario puede editar inputs y hacer submit, recibe un error genérico y no sabe que carece del permiso.

Evidencia reproducible sin credenciales: `scratchpad/qa/20260817T221922Z-e2e/evidence/ui-url-routes.jsonl` (deep-links `/#/team-settings/PB` status 200 por actor) y `permissions-write.jsonl` (casos `workflowStateCreate`/`labelCreate`/`cycleCreate` rechazados para roles no owner). El comportamiento de autorización de API es correcto; el problema es la affordance y el mensaje en UI.

## Comportamiento esperado

Para actors sin permiso de configuración del team, Team Settings debe ser read-only: ocultar o deshabilitar controles de escritura y mostrar un mensaje accionable indicando que solo un team owner o workspace admin puede editar. La API debe seguir siendo la autoridad final.

## Criterios de aceptación

- Owner del team conserva todos los controles y operaciones.
- Member y actor sin membership pueden leer lo permitido, pero no ven controles de mutación activos.
- Si una acción llega a ejecutarse por una carrera o deep-link, mostrar error accionable y preservar datos.
- Cubrir la matriz owner/member/outsider en pruebas de UI y GraphQL.
