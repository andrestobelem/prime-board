# SPIKE: decidir Workspace único o soporte multi-workspace

Created by admin.

## Pregunta de modelo

La referencia muestra una acción `Switch workspace`, pero prime-board está documentado y modelado como single-tenant: una única fila `workspace` por instalación.

## Evidencia

- `CONTEXT.md`: Workspace es la instalación entera y “no hay más de uno por instancia”.
- `docs/specs/mvp.md`: el producto es `single-tenant`.
- `apps/server/src/db/migrations/0001_init.sql`: existe la tabla singular `workspace`; teams, actors, projects y API keys no tienen pertenencia a un workspace.
- `apps/web/src/components/Sidebar.tsx`: el workspace se muestra como un bloque estático; no existe selector ni ruta de cambio.
- La captura de referencia incluye `Switch workspace`, por lo que copiar ese control sin una decisión de dominio produciría una affordance falsa.

## Entrega

Tomar una decisión explícita y registrarla en un ADR:

1. **Mantener single-workspace:** no implementar `Switch workspace` y ajustar el menú para no prometer una capacidad inexistente.
2. **Adoptar multi-workspace:** diseñar la migración de `workspace` a una entidad multi-tenant, memberships de workspace, alcance de actores/API keys, autorización, rutas, export/rebuild y aislamiento de datos.

## Criterios de aceptación

- [ ] Existe un ADR con la decisión y su motivación frente a la referencia visual.
- [ ] Si se mantiene single-workspace, se define la UI equivalente sin switcher.
- [ ] Si se adopta multi-workspace, el ADR enumera tablas, claves foráneas, auth, API, migraciones y tickets de implementación.
- [ ] No se implementa un selector visual desconectado del modelo.
