# GraphQL: paginar las conexiones de issues de proyectos y milestones

Created by admin.

## Hallazgo reproducible

Las conexiones anidadas anuncian `pageInfo.hasNextPage/endCursor`, pero no aceptan cursor:

1. Crear un proyecto con al menos dos issues.
2. Ejecutar `project(id: <id) { issues(first: 1) { nodes { identifier } pageInfo { hasNextPage endCursor } } }`: responde `hasNextPage: true` y un `endCursor`.
3. Ejecutar `project(id: <id) { issues(first: 1, after: <endCursor>) { ... } }`: GraphQL responde `Unknown argument "after" on field "Project.issues"`.
4. `Milestone.issues` tiene la misma forma truncada.

Evidencia: `packages/schema/src/sdl.ts:402,459` declara solo `first`; `apps/server/src/graphql/project-resolvers.ts:49-87` ignora `after` y no ofrece recorrido de página.

## Comportamiento esperado

Toda conexión que expone `PageInfo` debe aceptar `after` (y conservar orden estable) para que clientes puedan recorrer todos los issues sin perder datos.

## Criterios de aceptación

- Agregar `after` a `Project.issues` y `Milestone.issues` y resolverlo con el mismo cursor estable de `issues`.
- `hasNextPage/endCursor` permiten obtener exactamente la siguiente página.
- Mantener filtros por proyecto/milestone y límites 1..250.
- Agregar regresiones con múltiples páginas y recursos vacíos.
