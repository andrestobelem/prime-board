# Docs: sincronizar auditorías, Settings y runbook con el estado actual

Created by admin.

## Objetivo
Mantener la documentación de paridad y operación alineada con el código y el backlog actual.

## Evidencia
- Las auditorías canónicas de Linear citan snapshots anteriores a multi-Workspace y PostgreSQL.
- `PRB-382` a `PRB-395` siguen apuntando en sus descripciones al snapshot anterior, aunque `PRB-520` contiene la revalidación actual.
- El índice `docs/README.md` no cubre todos los documentos de investigación y operación vigentes.
- El procedimiento histórico de cutover puede confundirse con el runbook operativo actual.

## Criterios de aceptación
- [ ] `docs/audits/` identifica el estado actual de migraciones, Workspace, PostgreSQL y clientes.
- [ ] La documentación enlaza `PRB-520` y separa el snapshot histórico de la decisión vigente.
- [ ] `docs/README.md` incluye los documentos canónicos actuales y no enlaza archivos inexistentes.
- [ ] El procedimiento de cutover indica qué pasos son históricos y cuál es el runbook vigente.
- [ ] No se editan archivos generados de `.prime-board` a mano.
- [ ] Se ejecutan las validaciones documentales relevantes y se deja evidencia en el ticket.
