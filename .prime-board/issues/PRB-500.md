# Seed: Team.key se valida globalmente y bloquea keys válidas entre Workspaces

Created by admin.

## Hallazgo

La rama `builder/prb-473` (`5e50b80`) implementa `availableTeamKey` con consultas globales:

```sql
SELECT id FROM teams WHERE key = ?1
```

Después de integrar `scout/prb-472` (`58fbcc6`), `Team.key` es única por Workspace, no de forma global. Por eso un segundo Workspace no puede usar una key válida que ya existe en el primero; una key implícita también recibe un sufijo innecesario.

## Comportamiento esperado

La misma `Team.key` debe ser válida en dos Workspaces distintos y debe rechazarse solo cuando ya existe en el Workspace destino.

## Criterios de aceptación

- [ ] `availableTeamKey` consulta el Workspace destino.
- [ ] Una key igual en otro Workspace se conserva.
- [ ] Una key duplicada dentro del mismo Workspace se rechaza o genera la alternativa definida.
- [ ] Hay regresiones para ambos casos después de integrar PRB-472 y PRB-473.
