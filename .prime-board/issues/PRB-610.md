# UI: exponer Settings completos de Projects e Initiatives

Created by admin.

## Hallazgo

La superficie web no expone de forma completa los campos nuevos de Project e Initiative. Los contratos GraphQL, CLI y MCP incluyen `startDate`, members, dependencies, priority, leadTeam, labels, resources y updates, pero las vistas de Settings/Project/Initiative deben verificarse y completarse sin crear modelos duplicados.

## Comportamiento esperado

La UI debe mostrar y editar las propiedades soportadas por API, respetar ACL separadas y mostrar errores de validación. Debe reutilizar templates de PRB-385, notificaciones de PRB-386 y Views de PRB-390.

## Criterios de aceptación

- [ ] UI de Project expone start/target dates, lead, members, Teams, milestones y dependencies.
- [ ] UI de Initiative expone state, priority, owner, leadTeam, targetDate, labels, resources, updates y Projects.
- [ ] La UI no mezcla ACL de Project e Initiative ni habilita escritura sin permiso.
- [ ] Regresiones cubren carga, edición, validación y errores de autorización.
- [ ] Plan gates y DateTime/TimelessDate quedan visibles donde corresponda.

## Evidencia

HEAD `fd8d9663`: `apps/web` no contiene una superficie equivalente a los campos nuevos; GraphQL/CLI/MCP sí los exponen. Hallazgo independiente detectado durante PRB-391; primero verificar si existe otro Issue de UI antes de implementar.
