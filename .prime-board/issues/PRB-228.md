# AUDIT: revisión integral de prime-board

Created by admin.

## Objetivo

Hacer una auditoría integral del estado actual de prime-board para detectar errores, inconsistencias, contratos rotos, casos límite y problemas de documentación o integridad de datos.

Esta fase es de **revisión y registro**. No corregir hallazgos dentro de este ticket ni crear todavía los tickets de implementación: al terminar la auditoría se abrirá un issue separado por corrección o decisión.

## Alcance

- Calidad automatizada: tests, typecheck, build y errores reproducibles.
- API GraphQL y modelo de dominio.
- Persistencia, migraciones, logs, export/rebuild y round-trips.
- CLI, MCP, webhooks y paridad entre interfaces.
- Frontend desde el punto de vista funcional.
- Documentación, configuración, seguridad y consistencia operativa.

La comparación estética y de usabilidad con Linear queda fuera de alcance y será una etapa posterior.

## Método

1. Ejecutar las validaciones automatizadas y registrar sus resultados.
2. Revisar cada superficie mediante código y smoke tests reales.
3. Para cada hallazgo, documentar evidencia, comportamiento actual, comportamiento esperado e impacto.
4. Crear un issue de hallazgo, sin implementar la corrección todavía.
5. Comentar en este issue el resumen de lo revisado y enlazar los hallazgos.

## Criterios de salida

- Todos los sub-issues de auditoría están completados.
- Cada hallazgo accionable tiene un issue propio o una decisión explícita de no corregirlo.
- No quedan resultados ambiguos sin triage.
- Este issue contiene un resumen de comandos, superficies cubiertas y excepciones.
- Recién entonces se crean los tickets para corregir los hallazgos, priorizados por impacto.
