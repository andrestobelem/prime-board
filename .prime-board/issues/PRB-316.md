# Issues: excluir hijos archivados de la jerarquía activa

Created by admin.

## Hallazgo reproducible

Las conexiones de issues aplican reglas distintas a los archivados:

1. Crear un issue padre `PB-1` y un hijo `PB-2`.
2. Archivar `PB-2` con `issueArchive`.
3. Consultar `issue(identifier: "PB-1") { children { identifier archivedAt } }`.
4. `PB-2` sigue apareciendo en `children` con `archivedAt`, mientras las conexiones activas de issues/list/project lo excluyen por defecto.

Evidencia: el resolver de `Issue.children` usa `listChildren` sin filtro de archivado. No existe una operación pública de unarchive que permita gestionar esta inconsistencia desde CLI/MCP.

## Comportamiento esperado

La jerarquía activa debe excluir hijos archivados por defecto, igual que las demás listas, y ofrecer una opción explícita para incluirlos cuando se inspecciona historial.

## Criterios de aceptación

- `Issue.children` excluye archivados por defecto.
- Agregar `includeArchived` o una conexión histórica explícita si el contrato lo requiere.
- Mantener relaciones padre/hijo y export/rebuild sin perder referencias archivadas.
- Agregar regresiones para padre activo, hijo archivado y consulta explícita de archivados.
