# Rebuild: preservar API keys cuando cambia el nombre del actor

Created by admin.

## Hallazgo reproducible

`rebuildFromRepo` preserva las API keys capturando `actors.name AS actor_name` y re-vinculándolas mediante `actorIds.get(actor.name)`. El repo no conserva un identificador local estable de actor en `meta/actors.json`. Si el actor se renombra en la DB después de exportar un repo y luego se reconstruye desde ese repo (o existen dos snapshots con el nombre anterior/nuevo), la key queda sin correspondencia y desaparece sin diagnóstico; la autenticación de ese actor deja de funcionar.

## Evidencia

- `apps/server/src/export/importer.ts`: comentario y lookup de credenciales por nombre.
- `.prime-board/meta/actors.json`: guarda email/nombre/tipo/rol, no el id local.
- `apps/server/src/export/importer.test.ts`: prueba preservación por nombre, pero no rename entre snapshot y rebuild.
- `docs/adr/0004-repo-como-fuente-de-verdad.md` exige conservar las keys durante rebuild.

## Comportamiento esperado

La preservación debe usar una identidad estable independiente del nombre, o rechazar/diagnosticar de forma explícita una ambigüedad antes de borrar la DB. Un rename legítimo no debe invalidar la API key.

## Criterios de aceptación

- [ ] Un rename entre export y rebuild conserva la key y permite autenticar al actor renombrado.
- [ ] La vinculación no depende únicamente del nombre y maneja colisiones de nombres sin asociar silenciosamente.
- [ ] Si no se puede resolver una identidad, rebuild falla antes de borrar o produce un diagnóstico accionable.
- [ ] Export/rebuild continúa sin incluir hashes ni secretos en `.prime-board/`.
