# Workspace: implementar lifecycle de eliminación y evento deleted

Created by admin.

## Hallazgo de revisión de PRB-480

La revisión independiente de PRB-480 (`1f7a8cb`) confirmó que el runtime emite `workspace.created`, pero no implementa el lifecycle de eliminación de Workspace. No existe `workspaceDelete`, `deleteWorkspace`, `DELETE FROM workspace` ni emisión equivalente en los resolvers.

Esto deja incompleto el contrato de creación/eliminación de Workspace. La eliminación requiere definir primero la política de datos derivados, réplica, webhooks, credenciales y owner; por eso este ticket queda separado de la implementación de aislamiento y depende de PRB-414.

## Comportamiento esperado

El lifecycle de Workspace debe tener una operación de eliminación autorizada, transaccional y auditable. Debe emitir el evento de eliminación y aplicar una política explícita a Teams, issues, Activity, Webhooks, membresías, credenciales, réplicas y referencias.

## Criterios de aceptación

- [ ] PRB-414 y la política de eliminación están aprobados y completos.
- [ ] GraphQL expone una operación de eliminación de Workspace con autorización de admin.
- [ ] La eliminación no deja datos accesibles desde otro Workspace.
- [ ] El evento `workspace.deleted` contiene actor, Workspace y datos mínimos sin secretos.
- [ ] La operación es transaccional y tiene regresiones de autorización, aislamiento y replay/export.
- [ ] La réplica y los recursos derivados siguen la política documentada.

## Decisiones confirmadas — 2026-09-06

- `workspaceDelete` inicia un estado `Archived` reversible; no hace borrado físico inmediato.
- La retención es indefinida. No hay purge automático.
- Solo un Workspace Admin puede restaurar o iniciar el purge manual. El purge exige doble confirmación y un backup/export verificable.
- La Repository Replica conserva un namespace tombstoned con metadata y Event Log históricos. El tombstone bloquea acceso operativo, rebuild y restauración implícita.
- `workspace.archived` se emite al archivar y `workspace.deleted` solo después del purge físico.
- Ambos eventos requieren outbox durable y reintentos idempotentes. El payload no incluye secretos, hashes, URLs privadas ni tokens.
- Actors y API keys globales se conservan si tienen uso en otro Workspace.
