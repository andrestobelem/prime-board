# API: impedir que un update elimine el último estado COMPLETED del team

Created by admin.

## Hallazgo reproducible

`apps/server/src/domain/teams.ts:247-280` valida el tipo del workflow state durante `workflowStateUpdate`, pero permite convertir el único estado `COMPLETED` a `STARTED`. La protección equivalente existe solo en `deleteWorkflowState` (`:170-178`). En `scratchpad/audit-state.ts`, actualizar `Done` produce `success` y deja los tipos `BACKLOG, UNSTARTED, STARTED, STARTED, CANCELED`, sin ningún estado completado. Los tests `team-settings.test.ts:107-117` solo cubren borrar el último estado.

## Comportamiento esperado

El team debe conservar al menos un estado `COMPLETED`. Un update que convierta o elimine semánticamente el último debe fallar sin mutar el estado.

## Criterios de aceptación

- `workflowStateUpdate` rechaza convertir el único `COMPLETED` con `VALIDATION_FAILED` (o el error de dominio equivalente).
- El estado y sus issues quedan sin cambios después del rechazo.
- Se permite actualizar un estado `COMPLETED` cuando existe otro que conserva la invariante; si se admite una operación atómica de reemplazo, debe validarse como tal.
- Se agregan regresiones para update y delete y pasan los tests existentes.

## Duplicados/relación

PRB-164 (borrado de workflow states, Done) protege el delete, pero no este camino de update; no es duplicado exacto.
