# Documents: decidir soporte agent-first y política de migración

Created by admin.

## Decisión

Se incorpora un núcleo de Documents Markdown agent-first en SQLite. No se implementa una copia completa del editor colaborativo de Linear.

## Contrato

- Un `Document` pertenece al Workspace y puede vincularse a exactamente un recurso: `Issue`, `Project`, `Team`, `Initiative` o `Cycle`.
- El cuerpo es Markdown. La descripción de una Issue sigue siendo el resumen operativo; un Document es contenido largo independiente.
- El creador puede editar y los administradores del Workspace pueden gestionar documentos globales. Los documentos vinculados usan los permisos del recurso y los límites de Teams de la API key.
- La búsqueda cubre título y contenido. Archivo y restauración son reversibles.
- GraphQL, `pb document`, MCP y UI exponen listado, lectura, creación, edición, archivo y restauración.
- La Repository Replica conserva Documents en `.prime-board/meta/documents.json` con contenido, autoría, timestamps, archivo y referencias naturales. El round-trip export/rebuild está probado.

## Referencia Linear y límites intencionales

Linear también ofrece menciones, comentarios inline, suscripciones, historial de versiones, templates y colaboración en tiempo real. Esas capacidades quedan fuera de este corte. Adjuntos binarios y enlaces externos tampoco se convierten en Documents.

La migración PostgreSQL de Documents queda como seguimiento en `PRB-545`. Hasta completar ese ticket, el backend async no debe usar SQLite como fallback silencioso.

## Migración

Un import que entregue título y contenido crea un Document y conserva una referencia soportada. Un recurso de Linear que solo entregue URL se conserva como enlace con `warning`. Una pérdida o conversión no puede quedar silenciosa.

## Criterios cubiertos

- [x] Decisión de producto explícita.
- [x] Distinción entre Document, descripción Markdown, adjuntos y enlaces.
- [x] Scopes, ownership, permisos, búsqueda, export/rebuild y superficies GraphQL/CLI/MCP/UI.
- [x] Política de migración y reporte de pérdidas.
- [x] Documentación vigente actualizada en relevamiento, alcance, auditoría y migración.

## Fuera de alcance

Version history, comentarios inline, suscripciones, templates, colaboración en tiempo real y adjuntos ricos. La disponibilidad en PostgreSQL se sigue en `PRB-545`.
