# MCP: exponer Initiative Updates y sus inputs con Workspace seguro

Created by admin.

## Hallazgo

La revisión de PRB-391 encontró que las tools MCP de `list/get/save Initiative` no solicitan `updates` ni aceptan inputs para actualizar Initiative Updates. No deben crearse tools duplicadas si las tools genéricas pueden ampliar su contrato.

## Comportamiento esperado

El MCP debe exponer los Initiative Updates soportados por GraphQL con el Workspace efectivo de la sesión, sin cruzar IDs, cache ni permisos entre Workspaces.

## Criterios de aceptación

- [ ] `listInitiatives`/`getInitiative` incluyen updates y campos estables cuando corresponda.
- [ ] `saveInitiative` acepta solo inputs de update soportados y valida ACL/scope.
- [ ] Si el modelo exige una operación separada, se añade una tool única y documentada, sin duplicar operaciones existentes.
- [ ] Tests cubren sesión, Workspace, referencias homónimas, errores y compatibilidad legacy.
- [ ] Transporte HTTP/stdio conserva bearer/configuración y no filtra secretos.
- [ ] Typecheck, Prettier y diff-check pasan.

## Trazabilidad

Brecha detectada en la revisión independiente de PRB-391. No modificarla desde el branch de PRB-391.
