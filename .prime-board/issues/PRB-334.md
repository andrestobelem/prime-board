# UI: paginar Inbox y calcular correctamente el unread badge

Created by admin.

## Hallazgo reproducible

`App.tsx:42` consulta `inbox(first:50)` y calcula el badge en `App.tsx:489`; `InboxView.tsx:25-31` pide 250, no conserva `pageInfo` ni ofrece paginación. Además `listInboxActivity` limita resultados a 100 en `apps/server/src/domain/inbox.ts`. Con más de 50 entradas antiguas no leídas, el badge omite las que quedan fuera de la primera página y la vista no ofrece Load more para superar el límite.

## Comportamiento esperado

El badge debe representar el unread count completo y la Inbox debe permitir recorrer todas las entradas disponibles, con un contrato de paginación coherente entre API y UI.

## Criterios de aceptación

- El badge usa un conteo completo/endpoint dedicado, no una página truncada.
- Inbox ofrece continuación hasta `hasNextPage:false` y no pierde entradas por el límite de 100; si existe un límite intencional, debe tener cursor/contrato explícito.
- Marcar leído/archivar actualiza badge y lista sin inconsistencias.
- Regresiones con >50 y >100 entradas, incluidas no leídas antiguas.

## Duplicados/relación

PRB-284 implementó unread count/filtros, pero no volumen ni paginación; PRB-286 no cubre Inbox. No hay duplicado exacto.
