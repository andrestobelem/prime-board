# SQLite: compatibilizar triggers 0031 con autofill legacy de workspace_id

Created by admin.

## Hallazgo

La revisión de PRB-391 encontró que los triggers SQLite de la migración 0031 rechazan un `workspace_id` nulo con `workspace mismatch`. La migración 0025 establece un patrón de `AFTER INSERT` que completa el Workspace default en instalaciones singleton, y los comentarios de 0031 describen compatibilidad legacy.

## Evidencia

- En `createTestApp` singleton, un INSERT directo a `project_members`, `project_dependencies` o `initiative_updates` sin `workspace_id` falla con `workspace mismatch`.
- La migración 0025 autocompleta NULL en el singleton.
- Los triggers 0031 no exigen el par ni aplican autofill antes de validar; contradicen su comentario de compatibilidad.
- PRB-391 añade los triggers, pero no incluye una regresión que defina el comportamiento legacy.

## Comportamiento esperado

La compatibilidad single-workspace conserva el autofill legacy cuando el contexto es singleton. Un selector o `workspace_id` explícito de otro Workspace debe fallar cerrado. Con varios Workspaces, un `workspace_id` ausente debe exigir contexto explícito y no elegir un Workspace arbitrario.

## Criterios de aceptación

- [ ] Inserts legacy sin `workspace_id` completan el Workspace default solo en una DB singleton.
- [ ] El comportamiento cubre `project_members`, `project_dependencies`, `initiative_labels`, `initiative_projects` y `initiative_updates` según corresponda.
- [ ] Un `workspace_id` explícito de otro Workspace se rechaza sin persistir.
- [ ] Una DB multi-Workspace rechaza NULL con error explícito si no existe selector válido.
- [ ] Las regresiones cubren triggers 0025/0031, rollback y ausencia de bypass.
- [ ] Los comentarios de migración y documentación coinciden con el contrato.

## Trazabilidad

Hallazgo de revisión independiente de PRB-391. Registrar y corregir este Issue antes de modificar los triggers 0031.
