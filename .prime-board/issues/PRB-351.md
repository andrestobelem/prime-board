# Milestones: conservar referencias históricas cualificadas al borrar

Created by admin.

## Hallazgo reproducible

Al borrar un milestone, `deleteMilestone` guarda el tombstone como nombre corto cuando no hay duplicados actuales. Si luego se crea otro milestone homónimo en otro proyecto antes de exportar/reconstruir, el log histórico `M` queda ambiguo y el importer puede resolverlo al milestone equivocado.

## Comportamiento esperado

Las referencias históricas de milestones deben conservar siempre el proyecto, igual que las referencias cualificadas de otras entidades.

## Criterios de aceptación

- Tombstones de milestone usan siempre `Project/Milestone`.
- Import/export conserva la referencia histórica aunque aparezca un homónimo.
- Regresión para borrar, crear homónimo y reconstruir.
