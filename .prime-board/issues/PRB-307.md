# Webhooks: emitir cambios de relaciones en ambos issues

Created by admin.

## Hallazgo reproducible

Las relaciones actualizan Activity en ambos extremos, pero los webhooks no reflejan el cambio completo:

- `issueRelationCreate` en `apps/server/src/graphql/issue-resolvers.ts` emite un único `issue.updated` para `input.issueId`; el issue relacionado no recibe webhook.
- `issueRelationDelete` borra y registra Activity, pero no emite ningún `issue.updated`.

Un integrador suscripto a `issue.updated` puede quedar desincronizado aunque consulte la relación desde ambos issues. La guía de webhooks documenta `issue.updated` y que `changes` describe cambios.

## Comportamiento esperado

Crear o borrar una relación debe producir eventos consistentes para cada issue afectado, con tipo, issue relacionado y dirección correctos, o documentar explícitamente una semántica transaccional equivalente.

## Criterios de aceptación

- Crear relación notifica ambos extremos una sola vez cada uno.
- Borrar relación notifica ambos extremos y conserva payload identificable tras rebuild.
- Las entregas mantienen firma, ownership, reintentos y orden razonable.
- Agregar pruebas de webhook para `related`, `blocks` y `duplicate_of` desde ambos extremos.
