# Declarar el esquema de Activity: qué campos son referencia y a qué tabla

Created by admin.

De docs/adr/ (contexto): ADR-0004 dice que el repo es la fuente de verdad y SQLite un índice derivado. El log de eventos por issue (Activity) es la pieza que hace esa reconstrucción posible — pero hoy el conocimiento de "qué campo del payload de cada ActivityType es un id que refiere a otra tabla" no vive en ningún lugar declarado: está reimplementado como dos diccionarios calcados (uno por dirección) en exporter.ts y importer.ts, y falta por completo en el front (IssueView), que por eso no puede mostrar valores reales en el feed de actividad.

Qué construir: un módulo único, fuente de la verdad, que declare por cada ActivityType qué campos son referencia y a qué tabla (states, actors, projects, milestones, issues). No reemplaza todavía ningún call site — es el prefactor que hace fácil el cambio en las tickets siguientes.

Forma exacta a capturar (extraída del código real de exporter.ts::resolvePayload e importer.ts::denormalize, que hoy la mantienen en espejo):
  state_changed     → { from: states, to: states }
  assigned          → { from: actors, to: actors }
  project_changed   → { from: projects, to: projects }
  milestone_changed → { from: milestones, to: milestones }
  parent_changed    → { from: issues, to: issues }
  created           → { teamId: teams, stateId: states, assigneeId: actors, parentId: issues, projectId: projects, milestoneId: milestones }
  commented         → sin refs (el body ya viene resuelto, ver PRB-165)
  el resto (title_changed, description_changed, priority_changed, labeled, unlabeled, relation_added, relation_removed, archived) → sin refs
