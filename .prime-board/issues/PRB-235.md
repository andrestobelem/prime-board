# Auth: restringir administración de actores y API keys

Created by admin.

## Origen

Auditoría integral PRB-228 / sub-issue PRB-230.

## Evidencia

En una app/DB en memoria, un actor secundario autenticado pudo ejecutar `actorUpdate` sobre `admin` y `apiKeyCreate` para `admin`; ambas mutaciones devolvieron `success: true`.

## Problema

Cualquier actor con una API key puede renombrar actores y crear o revocar credenciales de otros actores.

## Comportamiento esperado

Aplicar autorización explícita: las operaciones administrativas deben requerir el rol adecuado y las operaciones personales deben limitarse al propio actor. La UI Members debe reflejar la misma regla.

## Criterios de aceptación

- [ ] Tests de acceso denegado para actor no autorizado.
- [ ] `actorCreate`, `actorUpdate`, `apiKeyCreate` y `apiKeyDelete` tienen una política documentada y aplicada.
- [ ] Un actor autorizado conserva la capacidad prevista.
- [ ] La UI no ofrece acciones que la API vaya a rechazar silenciosamente.
