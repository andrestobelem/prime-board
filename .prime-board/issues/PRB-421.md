# Documentación: consolidar diferencias de prime-board con Linear actual

Created by admin.

## Objetivo
Reunir en un documento canónico las notas dispersas que comparan prime-board con Linear actual y dejar clara la frontera entre paridad, divergencia intencional y gap.

## Alcance
- Revisar `docs/audits/linear-modelo-datos.md`, `docs/audits/linear-paridad-graphql.md`, `docs/audits/linear-paridad-visual-usabilidad.md`, `docs/research/linear-settings-parity.md`, `docs/relevamiento-linear.md`, `CONTEXT.md` y el schema/código vigente.
- Contrastar con fuentes primarias actuales de Linear (docs públicas/API) y, si es posible en el entorno, con observación de la instalación de Linear abierta; registrar fecha y limitaciones, sin automatizar ni modificar la cuenta.
- Comparar Workspace/Organization, Actor/User y memberships, Teams, Issues, Projects, Initiatives, Views, Inbox, Reviews, webhooks, auth, settings, import/export, UI y capacidades agent-first.
- Clasificar cada diferencia como `implementado`, `parcial`, `ausente`, `divergencia intencional` o `fuera de alcance`, con evidencia y enlaces.
- Añadir sección específica para multi-workspace: qué exige Linear y qué decide prime-board.

## Criterios de aceptación
- [ ] Existe un documento canónico en `docs/audits/` con fecha de relevamiento, fuentes, tabla comparativa y enlaces a código.
- [ ] No contradice el ADR/CONTEXT ni presenta como gap una divergencia decidida (local-first, actores agente, API keys, réplica Git).
- [ ] Cada gap tiene prioridad y ticket/referencia cuando aplica; se enlazan documentos anteriores sin duplicar su contenido.
- [ ] Se deja comentario con lo observado en la instalación de Linear o la limitación concreta si no fue accesible.
- [ ] La documentación queda preparada para actualizarse tras implementar la épica.
